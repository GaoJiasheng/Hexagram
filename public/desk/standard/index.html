书包格式标准

观象 · 书桌 · .deskbook · 第 1 版 · 工具 1.0.0

书包是「观象 · 书桌」读的书:一个 .deskbook 文件,本质是 zip,里面一份书目清单、每章一个 JSON 文件、再加图片和短视频。

它只装文字结构与媒体,不装任何网页、脚本或字体;版式由书桌统一排。典籍、现代书、文集三种体裁共用同一套格式。

任何人都可以照下面的标准做一本,导进自己设备上的书桌。导入的书只存在那台设备上,不上传。

三步做一本

  1. 写。用 Claude Code 装上下面的 skill,说「做一本书包」,它会先和你定提纲,再一章一章写;也可以手写 JSON,用 node deskbook.mjs init 目录 --kind book --title "书名" 起骨架。
  2. 校验与打包。node deskbook.mjs validate 目录 查出所有不合标准的地方,改到通过,再 node deskbook.mjs pack 目录 得到 .deskbook 文件。动图先用 gif2mp4 转成视频。
  3. 放进书桌。把文件隔空投送或存进「文件」,在手机上点开,选「用书桌打开」。

标准全文

「观象 · 书桌」读的每一本书,都是一个书包:一个 .deskbook 文件。

本标准公开:任何人都可以照它做一本书,导进自己的书桌。导入的书只存在自己的设备上,不上传、不收集。

实现与约定以本文件为准;机器可读的结构定义在 public/desk/standard/schema/,校验器 deskbook.mjs(单文件、无依赖)。

owner 2026-11-22 定的边界:公开账号只看到官方典籍;管理员账号另有「书房」一架(对象存储,含观书与管理员自己上传的);

任何用户都可以把书包导入自己的设备,只存本机。

0 · 三种体裁,一个格式

kind是什么一章里有什么阅读方式
classic 典籍以原文为主的书原文分段(segs:原文、译文、注),可带一篇深读文章(article)原文翻页;章末进深读
book 现代书一本书的讲解、消化,或自己写的书一篇文章(article)纵向长文
collection 文集若干独立文章:科普合集、一期刊物、专题一篇文章(article),各有作者、日期、出处目录是文章列表,纵向长文

三种共用同一套块(§3)与媒体规则(§4)。典籍沿用书桌现有的全部能力(详注、划线、卦画)。

1 · 书包的样子

.deskbook 是一个 zip(存储或 deflate,不加密,不嵌套 zip),解开后:

book.json            书目清单(必有)
chapters/001.json    每章一个文件,文件名 = 章号补零到三位
chapters/002.json
media/…              图片、视频、封面(可无)
  • 路径一律用 /,只许小写字母、数字、-、_、.;不许 ..、绝对路径、隐藏文件。
  • 只认上面三类内容。不收任何可执行内容:HTML、JS、CSS、SVG、字体、脚本一概不收;文字里的尖括号按字面显示。
  • 上限:整包 ≤ 300 MB;章文件 ≤ 2 MB;图片 ≤ 4 MB;视频 ≤ 24 MB;章数 ≤ 2000。

2 · book.json

{
  "format": "deskbook",
  "version": 1,
  "id": "u-neijing-daodu-3f9a2c1b",     // 稳定标识,见下
  "revision": 3,                         // 整数,每次重出 +1;书桌据此判断是不是新版
  "kind": "book",                        // classic | book | collection
  "title": "运动解剖学入门",
  "subtitle": "二十个动作讲清发力",       // 可无
  "authors": ["某某"],                    // 这本书包的作者(写讲解的人);可空数组
  "lang": "zh-Hans",
  "summary": "一句话说这本书讲什么(≤ 60 字)",
  "description": "一段介绍(≤ 400 字,可无)",
  "category": "健身",                     // 一个词,书架按它分栏;可无
  "tags": ["解剖", "力量训练"],            // ≤ 8 个
  "source": {                             // 内容从哪来(必有)
    "type": "digest",                     // original 原创 | digest 对别人的书的消化讲解 | public-domain 公版原文 | licensed 已获授权
    "of": { "title": "原书名", "author": "原作者", "publisher": "出版社", "year": 2019 },   // digest / licensed 必有
    "note": "可无"
  },
  "disclaimer": "medical",                // 可无;medical | divination | 或自写一句(≤ 120 字)。见 §6
  "unit": "章",                           // 章的叫法:章 / 篇 / 卦 / 讲 / 期…
  "theme": { "accent": "#2E7D86", "accent2": "#C7673F", "paper": "#F7F5EE" },   // 可无,缺了用默认
  "cover": "media/cover.jpg",             // 竖版 2:3,可无
  "banner": "media/banner.jpg",           // 横版 3:2,可无
  "parts": [ { "title": "上篇", "from": 1, "to": 8 } ],   // 可无;有则须连续覆盖全部章
  "chapters": [
    { "no": 1, "file": "chapters/001.json", "title": "肩胛骨先动", "subtitle": "可无", "minutes": 9,
      "author": "可无(文集用)", "date": "2026-10-03", "head": "media/head-001.jpg" }
  ],
  "generator": "deskbook-skill 1.0"       // 可无
}
  • id:[a-z0-9][a-z0-9-]{2,63}。官方典籍用短名(daodejing);其余一律带前缀,避免撞名:自己做的 u-<名>-<8 位随机十六进制>,书房的 g-<名>。同一本书重出不换 id,只加 revision——阅读进度、划线按 id 记。
  • chapters[].no 从 1 连续;file 必须存在;minutes 可无(书桌按字数估)。
  • head(章题头图,横版)可无。

3 · 章文件

{
  "no": 1,
  "title": "肩胛骨先动",
  // —— 典籍层(kind = classic 必有,其余不许有)——
  "segs": [
    { "o": "原文一段", "t": "译文(可无)", "label": "段名(可无)",
      "n": [ { "k": "被注的词", "d": "一句话释义(≤ 40 字)", "x": "展开(可无,40–150 字)", "r": "读音(可无)" } ] }
  ],
  "yanyi": ["章后的短延伸,一段一项(可无)"],
  // —— 文章层(book / collection 必有;classic 可有,即「深读」)——
  "article": {
    "title": "可无,缺则用章题", "subtitle": "可无", "idea": "一句话中心(可无,≤ 200 字)",
    "blocks": [ … ]
  }
}
  • 注 n:k 必须是该段 o 的精确子串;同段各条按首次出现位置互不重叠。
  • 典籍的 o 是底本原文:一个字不改,来源在 source 里交代。

块(blocks)

文字里只有三种行内记号:**加粗**(成对)、` 等宽 、文字` 链接(只许 https,点了先问再用系统浏览器打开)。别的记号按字面显示。

t字段说明
leadx导语
h2 / h3x小标题(两级)
px正文段
quoteo? tr? x? by?引文。典籍:o 原文 + tr 译文;其余:x 引的话 + by 出处
callouttone label? items[]提示框。tone:note tip warn
pullx金句(一章至多 1 处)
stepsitems[]有先后的步骤
listordered items[]列举
outlineitems[]多级提纲 / 思想脑图。每项 {x, children?},最多四层
figfig cap?图解:结构化数据(对比 / 列举 / 流程 / 结构 / 时间线 / 表格 / 卦画 / 方位 / 金句卡),由书桌用原生版式画。字段见 schema/fig.json,与 docs/desk-baihua-spec.md §2 同
imgsrc alt cap? w h图片。w h 是像素尺寸(排版占位用)
videosrc poster cap? w h sec loop? sound?视频 / 动图。默认循环、静音、进入屏幕自动播,点一下暂停;sound: true 的不自动播
codex lang?代码或等宽文字
divider—分隔
refsitems[]文末出处、参考
  • 每章至少一个 p 或 lead;空块不许有。
  • 不认识的 t 书桌会跳过(以后加新块不破旧版本),但校验器当错误报——照标准写的包里不该有。

4 · 媒体

  • 图片:.jpg .png .webp;长边 ≤ 4096。照片用 jpg,线条图用 png / webp。
  • 动图一律转成视频:.mp4(H.264,yuv420p,+faststart),长边 ≤ 1280,≤ 60 秒,无声或 AAC。GIF 不进包——同样的画面,GIF 往往大十倍以上。校验器带一条转换命令:deskbook.mjs gif2mp4 a.gif(需本机有 ffmpeg),同时出一张封面图 poster。
  • 每个 img / video 块引用的文件必须在包里;包里没人引用的媒体校验器会提示。
  • 封面、题图、章题头图不带文字(书名由书桌用字体排上去)。

5 · 文字口径(做书的人要守的)

  1. 版权。source.type = digest(讲别人的书)时:全文绝不进包,文章是自己的话;直接引用每条 ≤ 100 字、每章 ≤ 16 条(quote 块里算),不得靠拼引文还原原书;不用出版社的封面与插图。校验器按这两个数卡。
  2. 典籍:原文取通行底本并在 source.note 写明;译注讲训诂、思想、史实,有争议并陈不裁断。
  3. 不编造出处。拿不准的引文、年代、数据不写,或明说「未能核实」。
  4. 一章一个中心,先说结论再展开;图解与动图是为了讲清一件事,不为装饰。

6 · 红线与声明

disclaimer什么时候必须带书桌显示内容上的约束
medical讲医学、养生、健身、营养、心理治疗书的首页与每章开头:「本书为知识研习,不构成医疗建议;身体不适请就医」不给诊断、处方、剂量;不承诺疗效;健身动作写明量力而行
divination讲命理、占卜、风水、相术「本书为文化与文献研习,不作预测与决断依据」讲「书里怎么说、为什么这么说」,不替人断命,不下吉凶断语

校验器:category / tags 命中上述领域而没带对应声明,报错。其余题材不需要声明。

7 · 工具

deskbook.mjs(Node 18+,单文件,无依赖):

node deskbook.mjs init <目录> --kind book --title "…"     # 起一个骨架
node deskbook.mjs validate <目录 | 书包>                    # 校验:结构、引用、上限、口径上的硬数、声明
node deskbook.mjs pack <目录> [-o 书名.deskbook]            # 校验通过后打包
node deskbook.mjs unpack <书包> [-o 目录]
node deskbook.mjs gif2mp4 <a.gif> [-o media/a.mp4]         # 动图转视频 + 封面图(需 ffmpeg)

校验不过不打包。错误信息指到「哪个文件、哪一块、为什么」。

8 · 书怎么到书桌上

来路谁能看到怎么放
官方典籍所有人随观象网站托管(/desk/v1/),书桌的「添书」里就有
书房只有管理员账号对象存储。在观象网站的管理页上传 .deskbook(或命令行 npm run desk:publish <书包>);书桌的「添书」里,管理员多一栏「书房」,按 category 分栏
自己导入只在导入的那台设备上把 .deskbook 传到手机(隔空投送、文件、分享菜单、或粘贴一个 https 链接),用书桌打开。不上传
  • 自己导入的书可以再原样分享出去(还是一个 .deskbook);划线与批注可以导出成 Markdown。
  • 阅读进度、时长、划线照常跟账号同步(按书的 id),书本身不同步:换一台设备要再导入一次。
  • 书桌里「我的 → 自定义导入」是这份标准的入口:讲三步怎么做、给标准与工具的下载、导入按钮。

9 · 版本

  • version: 1。以后只加不改:加字段、加块类型、加 fig 的 kind;书桌遇到比自己新的 version 会提示升级 App,而不是硬读。
  • 本标准、结构定义、校验器、做书用的 skill 都公开在 https://hexa.gavin.pub/desk/standard/。

附录 · 图解 fig 的字段

摘自 docs/desk-baihua-spec.md §2(书桌白话图解的格式,本标准的 fig 块原样沿用;机器可读版见 schema/fig.json)。

那份说明写的是「把站内的 SVG 图转成结构化数据」,文中的「原图」指转换的来源图;自己做书时,理解成「你想画的那张图」即可。

书包里不放 SVG;那边「与 SVG 字字相等」的闸不适用于书包,其余两条(结构合法、单个字符串 ≤ 120 字)由校验器照核。

公共字段

  • kind:下列十种之一。
  • title?:图题(图里最上面那行大字)。
  • foot?:[字符串],图最下面的总结 / 说明行,一行一项。
  • 任何「条目」都可带 accent: true——原图里用朱色强调的那一条。

十种 kind

quote 金句卡 —— 一句原文为主的卡片。

{ "kind": "quote", "text": "夫唯弗居，是以不去。", "gloss": "正因为不居功，功绩才不会离他而去。", "source": "《道德经 · 二章》" }

gloss、source 可选。原图角上的「观象」印章字不收。

cols 并列 / 对比 —— 两到四栏,每栏一个栏头和若干行。

{ "kind": "cols", "title": "看世界的两只眼睛,都得睁着",
  "cols": [ { "head": "常无欲 · 观其妙", "lines": ["放空功利心地看", "看见整体·本源·微妙", "像静静看娃玩", "只用这只 → 易飘、空谈"] },
            { "head": "常有欲 · 观其徼", "lines": ["带着目的去看", "看清轮廓·边界·苗头", "像评估娃的能力", "只用这只 → 易窄、短视"] } ],
  "foot": ["两个「常」字并列:不是二选一,是两副眼都常用"] }

栏里若是「小标题 + 说明」成对出现,lines 的项可写成 { "head": "慈 → 能勇", "body": "有要护的人，豁得出去" }。

rows 列举 / 层次 / 一览 —— 自上而下的若干条。

{ "kind": "rows", "title": "「道之贵」的四层递进",
  "items": [ { "mark": "一", "head": "无所不庇", "body": "万物之奥 · 善人宝,不善人所保" }, … ],
  "foot": ["贵不在稀有难得,而在普惠不挑人"] }

mark(序号、标签)与 body 可选;body 可为字符串或字符串数组。

flow 流程 / 推理链 / 阶梯 / 循环 —— 有先后的若干步。

{ "kind": "flow", "title": "四句话,一条推理链",
  "steps": [ { "head": "天地不仁", "body": "天道:不偏私" }, { "head": "圣人不仁", "body": "治道:别折腾" }, … ],
  "result": { "head": "夫唯不争，故无尤" }, "loop": false }

result(链条最后落到的结论,原图里单独画的那一格)可选;loop: true 表示首尾相接的循环。

tree 结构 —— 一个根,若干分支,分支下可再有一层。

{ "kind": "tree", "title": "三个「不」，堵三个钩子",
  "root": { "head": "…" },
  "branches": [ { "head": "不尚贤", "body": "堵住「争」" }, { "head": "不贵难得之货", "body": "堵住「盗」" }, { "head": "不见可欲", "body": "堵住「乱」" } ] }

root 可省(原图只有并排的几支时);分支可带 children: [{head, body?}]。

timeline 时间线 / 版本流变

{ "kind": "timeline", "title": "「绝圣弃智」一句的版本流变",
  "points": [ { "when": "战国", "head": "郭店楚简本", "body": "多释「绝智弃辩」" }, … ] }

when 可省(原图没有明确时间时)。

table 表格 —— 有行有列、每格都短的图。

{ "kind": "table", "title": "…", "heads": ["卦", "象", "德"], "rows": [["乾", "天", "健"], ["坤", "地", "顺"]] }

heads 可省。

gua 卦画 —— 图里画了卦(六画卦或三画卦)的。卦画由 App 按卦名自己画,数据里只写卦名与文字。

{ "kind": "gua", "title": "乾卦 · 六爻自下而上（全是阳爻）",
  "guas": [ { "name": "乾", "form": "hex" } ],
  "yao": [ { "label": "上九", "text": "亢龙，有悔（飞过头了）" }, { "label": "九五", "text": "飞龙在天（鼎盛 · 卦主）", "accent": true }, … ],
  "foot": ["六条实线＝六阳爻；读卦从最下「初九」往上读到「上九」"] }
  • guas[]:图里画出的每一个卦。name 是卦名(六十四卦名或八经卦名:乾坤震巽坎离艮兑),form 是 hex(六画)或 tri(三画);可带 head(这个卦旁边的标题,如「综卦：上下颠倒」)与 lines(它名下的几行说明)。
  • yao[]:只画一个六画卦、且逐爻有标注时用,自上而下(上爻在前,与图同);label 是爻题,text 是那一爻旁的字。
  • 上下卦分解图:guas 里放两个 form: "tri",head 写「上卦 ☷ 坤 为地」里的字(符号 ☷ 不收)。
  • 原图里的卦符号(䷀…䷿、☰…☷)不收,App 自己画。

ring 方位 / 环形 —— 先天后天八卦方位、四时循环一类按方位摆的图。

{ "kind": "ring", "title": "后天八卦方位", "center": "…",
  "items": [ { "at": "S", "head": "离", "body": "火 · 夏" }, { "at": "SW", "head": "坤", "body": "地" }, … ] }

at 取 N NE E SE S SW W NW 之一,按原图上的位置填(古图上南下北:画在正上方的填 S 还是 N,以图中文字标的方位为准,没标就按画面上方为 S)。center 可省。

notes 兜底 —— 以上都不合适时,只保留文字:{ "kind": "notes", "title": "…", "lines": ["…", "…"] }。
