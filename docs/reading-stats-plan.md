# 研读统计(个人 + 管理员)· 分析与方案(2026-10-01,等 owner 拍板,未开工)

> owner:「个人设置页能不能加统计:历史看过哪些、停留时长、总计/平均、历史 / 30 天 / 7 天 / 今天;
> 管理员页也能看用户统计,既看跨用户的,也能 by 用户分析。你帮我分析分析。」

## 0 · 结论先说

**能做,而且一半的地基已经在了**;真正要先定的不是技术,是一条**隐私承诺**——现在的隐私页白纸黑字写着:
阅读埋点是匿名的、「即使你已登录仍无法回溯到你」,云同步数据「不做分析、不做画像」。
「管理员按用户看停留时长」正好撞在这两句上。所以方案分三层,**前两层不动承诺、第三层要改承诺并给用户开关**:

| 层 | 给谁看 | 数据在哪 | 动不动隐私承诺 | 工作量 |
|---|---|---|---|---|
| **A 个人研读统计** | 用户自己 | 本机 localStorage;登录后随现有云同步走(只为换设备接着看) | 只需在「同步哪些数据」清单里加一项「阅读时长记录」 | 1.5 天 |
| **B 管理员 · 跨用户** | 你 | 现有匿名埋点 `reading_events`(cid,不关联账号)加窗口与分布 | 不动(仍是聚合趋势) | 1 天 |
| **C 管理员 · 按用户** | 你 | 新表 `reading_daily(user_id, day, 书, 章, 秒)`,**只收登录且开了开关的人**,只存日聚合 | **要改**:隐私页两处 + 设置里明示开关 | 1.5 天 |

我的建议:**A + B 先做,C 做成默认关的自愿开关**(「把我的研读时长计入账号,便于站长了解读者怎么读」),
这样跨用户的判断靠 B 的匿名群体数据,按用户的分析只落在明示同意的人身上,承诺改得最小。

## 1 · 现状:已经有什么

- **匿名阅读埋点**(`src/features/telemetry.js` → `POST /api/beat` → D1 `reading_events`):浏览器首访生成匿名 cid;
  换路由 / 页面隐藏 / 离开时 `sendBeacon` 一条 `{cid, path, corpus, slug, chapter, dwell_ms}`,服务端附 Cloudflare 边缘解析的国家/省。
  **停留是墙钟时间**(进页到离页),没有「没在看」的判断;iOS 壳(`VITE_CAP`)里不发。
- **管理员统计页** `/admin/stats`(`src/features/admin/AdminStatsPage.jsx` ← `GET /api/admin/stats`):
  近 7 天每日事件数、各组热度、Top 10 章、平均停留、国家 / 中国省份排行。**没有**时间窗切换、没有按 cid 的分布、没有「多少人」。
- **云同步**(`POST /api/sync` → `user_data(user_id, key, value)`):登录后按 `DATA_KEYS` 白名单整份快照合并,
  现有 `reading`(章级续读)、`readPos`(段级)、收藏 / 批注 / 占例 / 学堂进度 / 设置。**加一个键就自动跟着同步**。
- **个人页**:各组 `/<组>/me`(续读 / 收藏 / 批注 / 里程碑 / 备份提示)、易经 `/me`、设置浮层(账号 / 主题 / 译文 / 格律 / 字体 / 导出导入)、
  首页「我的研读」跨组足迹。**都没有时长**——本机只记「读到哪」,不记「读了多久」。
- **隐私页**(`src/features/PrivacyPage.jsx`,头注写明「写错是合规问题,改功能务必回来改」):
  §二 云同步数据「不做分析、不做画像」;§四 匿名统计「不与登录账号关联……无法回溯到你」。

## 2 · 需求拆开看

| owner 要的 | 落在哪一层 | 备注 |
|---|---|---|
| 历史看过哪些内容 | A(本机日志)| 已有 `reading/readPos` 只记最后位置;要「看过哪些」得记一份**按时间的日志** |
| 每次停留、总计、平均 | A | 口径见 §4:要算「活跃时长」不是「开着页面的时长」 |
| 历史 / 30 天 / 7 天 / 今天 | A、B、C | 按日聚合一次,四个窗口都是切片 |
| 管理员看跨用户 | B | 匿名 cid 就够:多少人、看多久、看什么、回访几次 |
| 管理员 by 用户 | C | 只能是登录 + 同意的人;匿名 cid 按承诺不能对到人 |

## 3 · 三层各怎么做

### A · 个人研读统计(本机为主)

**记什么**:一条阅读会话 = `{t 开始时间, corpus, slug, ch, sec 活跃秒数}`。落本机 `readLog` 键:
最近 500 条会话原样保留(给「最近看过」列表);更早的只留**按日 × 书的秒数**(给 30 天 / 历史)。
一年顶多几十 KB。纳入 `DATA_KEYS` 即随登录同步(合并规则:按日相加、会话按 id 去重)。

**怎么算时长**(§4 详述):页面可见 + 60 秒内有滚动 / 点击 / 按键 才计时;单次上限 30 分钟;换章即切会话。

**在哪看**:
- 设置浮层加一节「研读统计」:三个数(今天 / 近 7 天 / 累计)+「查看详情 →」;
- 新页 `/stats`(中立外壳,与 `/concepts` `/timeline` 同款):
  - 顶部四档切换 今天 / 7 天 / 30 天 / 历史,每档给 **总时长 · 次数 · 平均每次 · 读过几部几章**;
  - 一张**日历热力图**(近一年,一格一天,深浅 = 当天分钟;与 GitHub 贡献图同款,古书站可以做成「墨点」);
  - **常读的书**条形图(按时长)+ 点进去看到章;
  - **最近看过**列表(时间 · 书 · 章 · 停了多久,点回原章);
  - 各组 `/<组>/me` 顶部各加一行「本组累计 X 小时 · 最近 7 天 Y 分钟」。
- 一句提示放在页尾:「统计只在你的浏览器里算;登录后随研习数据一起同步,站长不看这一份。」(与承诺一致)

**iOS 壳**:本机统计照常;同步走现有 `/api/sync`,不受 `VITE_CAP` 禁埋点影响。

### B · 管理员 · 跨用户(匿名,不动承诺)

在现有 `reading_events` 上加:
- 时间窗切换(今天 / 7 / 30 / 全部);
- **人数**:窗口内活跃 cid 数(DAU / WAU / MAU)、新 cid vs 回访 cid;
- **时长**:总停留、平均、**中位数**(平均被挂机拉高,中位数才像人)、分布直方图(<1 分 / 1–5 / 5–15 / 15–30 / >30);
- **回访**:每 cid 的会话数分布(来一次就走的占几成、来过 5 次以上的几个);
- 内容:各组 / 各书 / 各章 Top,按**时长**排一次、按**次数**排一次(现在只有次数);
- 留存:本周活跃 cid 里上周也来过的比例。
仍是「多少人、看多久、看什么」的群体图,不列单个 cid 的清单——列了就是画像,承诺里没这一条。

顺手要改两处埋点:① 停留改活跃时长口径(与 A 同一套算法),否则平均值全是挂机;② 长时间阅读加**每 5 分钟一次心跳**,
iOS Safari 的 `pagehide` 经常不触发,一小时的阅读现在可能整条丢掉。心跳条目带同一个 session id,服务端按 id 累加,
不会多算。写入量:一个读者一小时 12 条,D1 与 Pages Functions 的免费额度够用几个量级。

**保留**:原始事件只留 90 天,之后按日 × 内容滚成汇总表(`reading_rollup_daily`),否则表只涨不落。

### C · 管理员 · 按用户(要改承诺,做成自愿)

- 设置「账号」一节加开关:**「把我的研读时长计入账号」**,默认关,旁边一句说明「开了之后站长能看到你读了哪些书、读了多久,用于了解读者怎么读;随时可关,关了就不再上传」。
- 开着时,客户端把 A 层的**日聚合**(不是逐次会话)随 `/api/sync` 一起送,服务端落 `reading_daily(user_id, day, corpus, slug, ch, seconds, views)`。
  只存日 × 章的秒数,不存时刻、不存路径、不存地理。
- 管理员页加「读者」一栏:开了开关的用户列表(昵称 + 头像种子,**不显示邮箱**)、最近活跃日、累计 / 30 天 / 7 天时长、常读的书;点进去看该用户的日历热力图与章级明细。
- **隐私页改三处**:§二 同步数据清单加「阅读时长记录」(仍写明不做画像——这一份是你自己的统计);
  §二 或新增 §五「自愿的读者统计」:开关默认关、开了收什么、站长看得到什么、怎么关、关了怎么删;
  §四 匿名统计那段不动(cid 仍不关联账号)。关于页「你的数据」一节同步改一句。
- 已登录但没开开关的人,与游客一样只进匿名 B 层。

**不建议**的做法:把 cid 直接挂到账号上「顺便」得到按用户数据——它推翻的是承诺里最明确的一句,而且 cid 是浏览器级的,一台电脑几个人用就串了。

## 4 · 「停留时长」的口径(A/B/C 共用一套,最容易做错的地方)

- **活跃时长 ≠ 页面打开时长**。规则:页面可见(`visibilitychange`)且**最近 60 秒内有过滚动 / 点击 / 按键 / 触摸**才计时;
  连续 60 秒无操作暂停,再有操作从头计;切到别的标签页、锁屏即暂停。
- **单次上限 30 分钟**:再长的一次会话按 30 分钟计(防止挂一夜)。一章读半小时以上的人,重新有操作会开新会话,不丢。
- **换章即切会话**:统计单位是「章」(与站内所有索引一致);首页 / 门户 / 目录页只计入「本站总时长」,不计入某本书。
- 白话抽屉、整页白话算在所属那一章上;金句卡、搜索面板不单算。
- 平均值旁边一定给中位数;个人页给「平均每次」,管理员页给分布。

## 5 · 工作量与顺序

| 步 | 内容 | 估 |
|---|---|---|
| 1 | 活跃时长测量器(一个 hook,A/B 共用)+ 本机 `readLog` + 纳入同步白名单 | 0.5 天 |
| 2 | `/stats` 页 + 设置浮层摘要 + 各组 /me 一行 | 1 天 |
| 3 | 埋点改口径 + 心跳 + 服务端按 session 累加 + 90 天滚存 | 0.5 天 |
| 4 | 管理员页:时间窗、人数、中位数与分布、回访、按时长的 Top | 0.5 天 |
| 5 | (若做 C)开关 + `reading_daily` + 管理员「读者」栏 + 隐私页三处 | 1.5 天 |

A + B 约 2.5 天可上生产;C 另 1.5 天,且要你先定文案。数据是从做好那天起算的,**不会有历史**——想早点有数,步 1 可以先单独上。
