## 1. 二期定位与原则

### 1.1 范围一句话

- **M4 · 明**:术语层(别名、TermTip、名词表)+ 卦内视角补全(贞悔、三才、爻位身份)。
- **M5 · 宫**:京房八宫 + 纳甲装卦引擎(全算法生成),详情页纳甲表、总览页八宫视图。
- **M6 · 占**:梅花易数(时间/数字起卦 + 体用断)+ 学堂改版(河图洛书、十二消息卦、大衍演示)。

### 1.2 学习友好五原则(不可妥协)

1. **渐进披露**:所有二期高级内容(纳甲表、八宫、体用)默认折叠或在新入口里,**一期页面的默认信息密度一丝不增**。每个折叠头部带一句白话:"纳甲——给每一爻配上天干地支,是汉代六爻占法的底盘"。
2. **概念首现必有解释**:任何术语第一次出现在某页时,必须是 `TermTip` 包裹(§3),hover/点按即见一句白话;名词表(学堂第五篇)兜底。
3. **推导过程可见**:梅花起卦显示完整算式、八宫显示变爻路径、大衍逐步演示。让用户**看见算法**,而不是只看到结果——这是本站和算命网站的本质区别。
4. **语气延续 v1 §6.4**:传统断法照录、注明出处(《梅花易数》《易学启蒙》),陈述"传统断法谓之…",不渲染吉凶、不加恐吓性或诱导性文案。
5. **新内容都连回经文**:八宫视图每格可进卦详情;消息卦环每卦可点;大衍成卦后一键带动爻进工作台。学的是体系,落点永远是读卦。

## 5. 八宫与纳甲(M5)— 全部算法生成,palace 字段不再人工填

> 新模块 `engine/bagong.js`、`engine/najia.js`。**hexagrams.json 不改动**,八宫与纳甲全部运行时计算——这是派生数据,不入数据管线。同步更新 CLAUDE.md,移除"palace 待填"待办。

### 5.1 八宫生成算法(bagong.js)

每宫从本宫卦(八纯卦,上下同经卦)出发,对 binary(下标 0=初爻)做**累积**变换:

| 代别 | 操作(在前一代基础上) | 世爻位 |
|---|---|---|
| 本宫(上世) | — | 6 |
| 一世 | 翻转初爻(idx 0) | 1 |
| 二世 | 再翻二爻(idx 1) | 2 |
| 三世 | 再翻三爻(idx 2) | 3 |
| 四世 | 再翻四爻(idx 3) | 4 |
| 五世 | 再翻五爻(idx 4) | 5 |
| 游魂 | 五世基础上翻回四爻(idx 3) | 4 |
| 归魂 | 游魂基础上下卦三爻复原为本宫 | 3 |

- **应爻** = 世爻隔二:世1应4、2应5、3应6、4应1、5应2、6应3。
- **宫五行**:乾兑金、离火、震巽木、坎水、艮坤土。
- API:`getPalace(binary) → { palaceTrigram:'kan', palaceName:'坎宫', generation:'二世', shi:2, ying:5, element:'水' }`,内部построй一次 64 卦→宫 Map。
- **自检用例(必入单测)**:
  - 坎宫全序列:坎→节→屯→既济→革→丰(五世)→明夷(游魂)→师(归魂)。
  - 屯 = 坎宫二世,世 2 应 5。
  - 乾宫归魂 = 大有;八个本宫卦各归本宫、世在上爻。
  - 64 卦恰好均分八宫、每宫 8 卦无重复(全量断言)。

### 5.2 纳干支(najia.js)

**天干**(内卦/外卦):乾内甲外壬、坤内乙外癸;震庚、巽辛、坎戊、离己、艮丙、兑丁(内外同)。

**地支**(每经卦六位表,取法:该经卦做下卦用前三位、做上卦用后三位;自下而上):

| 经卦 | 初→上六位 |
|---|---|
| 乾 | 子 寅 辰 午 申 戌 |
| 震 | 子 寅 辰 午 申 戌 |
| 坎 | 寅 辰 午 申 戌 子 |
| 艮 | 辰 午 申 戌 子 寅 |
| 坤 | 未 巳 卯 丑 亥 酉 |
| 巽 | 丑 亥 酉 未 巳 卯 |
| 离 | 卯 丑 亥 酉 未 巳 |

## 6. 梅花易数模块(M6)

> 新模块 `engine/meihua.js`。梅花的时间/数字起卦是**确定性**算法(同一时刻/同一组数必得同一卦),与本站气质完全契合。

### 6.1 农历依赖

- 引入 `lunar-javascript`(纯计算库,无 UI,不违反"不引 UI 库"约定),**仅在工作台梅花面板内 `import()` 懒加载**。
- **解耦设计(关键)**:`meihua.js` 的核心函数只收数字(年支序数、月、日、时支序数),**不依赖日历库**;日历换算写成独立薄适配 `lunarAdapter.js`(Date → { nianZhi, yue, ri, shiZhi, 显示用农历字符串 })。单测全部打在核心函数上;适配层只测一个人工核对过的已知日期 + 字段范围合法。

### 6.2 起卦算法

**通用数表**:先天卦数 乾1兑2离3震4巽5坎6艮7坤8(恰好等于 TRIGRAM_ORDER 下标+1);地支序数 子1丑2…亥12;时辰由小时数换算 `branchIndex = Math.floor(((h + 1) % 24) / 2)`(23:00–00:59 为子时)。**所有取余:余 0 取除数本身**(%8 余 0 → 8 坤;%6 余 0 → 6 上爻)。

| 起卦法 | 上卦 | 下卦 | 动爻 |
|---|---|---|---|
| 时间起卦 | (年支数+农历月+农历日) % 8 | (年支数+月+日+时辰数) % 8 | (年支数+月+日+时辰数) % 6 |
| 数字起卦 | 数一 % 8 | 数二 % 8 | (数一+数二) % 6 |

- 数字起卦取最通行的两数版;流派差异(加时辰等)在面板下方小字注明一句即可。
- **自检用例(必入单测,即《梅花易数》观梅典故)**:年支辰(5)、农历十二月、十七日、申时(9) → 上卦 (5+12+17)%8=2 兑;下卦 (34+9)%8=3 离;动爻 43%6=1 初爻 → **泽火革,初爻动,变泽山咸**(binary:革 101110 → 咸 001110)。

### 6.3 体用与生克(`tiYong()`)

- 动爻在下卦(1–3)→ 下卦为**用**、上卦为**体**;动爻在上卦(4–6)→ 上卦为用、下卦为体。
- 经卦五行:乾兑金、离火、震巽木、坎水、艮坤土。
- 体用关系五型(固定文案,克制语气,出处《梅花易数·体用总诀》):

| 关系 | 传统断语(照录,前缀"传统断法谓之") |
|---|---|
| 用生体 | 顺遂有助 |
| 比和(同五行) | 谋事易成 |
| 体克用 | 可成而费力 |
| 体生用 | 泄耗,劳而少功 |
| 用克体 | 多阻,不利 |

- **参断**:互卦上下两经卦各与体生克(谓"事之中");变卦中用卦变成的新经卦与体生克(谓"事之终")。输出三行结构化结果,不做综合吉凶结论——把三段关系摆出来,判断留给学的人。
- 续上例自检:革初爻动,动在下卦 → 用=离(火)、体=兑(金),火克金 → **用克体**;变卦咸,用卦离变为艮(土),土生金 → 变卦生体。

### 6.4 工作台 UI 增量

- 起卦分段控件改四项:`[上下卦 | 逐爻 | 检索 | 梅花]`。
- **梅花面板**,内部两个小 tab「时间起卦 / 数字起卦」:
  - 时间:默认"此刻",自动填农历(显示"丙午年 五月初七 酉时"样式,每个数字可手改——手改即教学);下方**完整算式**实时显示:`(年7 + 月5 + 日7) ÷ 8 余 3 → 离` 三行,`--ink-soft` 等宽数字。
  - 数字:两个数字输入(1–999)+ 同样的算式展示。
  - 「起卦」按钮 → 设定本卦与动爻(走既有状态,右栏全部既有卡照常工作)。

### 7.2 第三篇 · 十二消息卦 `/basics/xiaoxi`

- 引擎补一个常量模块(可生成可校验):阳息序列 复(1 阳在下)→临→泰→大壮→夬→乾,阴消序列 姤(1 阴在下)→遁→否→观→剥→坤。每项配:农历月(十一月起)、地支(子起)、节气中气。单测断言 12 卦名次序与 binary 规律(下 k 位同、余位反)。
- **环形 SVG**(视觉主角):12 卦按钟面排列,子(复)居正下,顺时针;每位 = sm 卦画 + 卦名 + 月份/地支微字。hover → 该位放大 10% + 中心显示详情一行;点击 → 卦详情页。环中心默认显示"阳息阴消"四字。
- 配文:消息卦即"十二辟卦",阳气自复而息、自姤而消;两段讲完,不展开卦气六日七分(后置)。

### 7.3 第四篇 · 揲蓍成卦 `/basics/shicao`

把《系辞》"大衍之数五十,其用四十有九"做成**逐步演示**。

- **引擎 `engine/dayan.js`(纯函数,rng 注入)**:
  - `castLine(rng) → { value: 6|7|8|9, steps: [...] }`:三变,每变 = 分二(rng 决定分点,两堆各≥1)→ 挂一 → 两堆各揲四取余(余 0 计 4)→ 归奇(第一变必为 5 或 9,二三变必为 4 或 8)→ 去归奇。三变后余 24/28/32/36 ÷ 4 → 6/7/8/9(老阴/少阳/少阴/老阳)。
  - `castHexagram(rng)`:六次 castLine,自下而上。
  - 单测:固定种子的 rng 断言完整 steps 复现;任意 rng 下断言中间量合法域(上一行括号内的约束)与输出 ∈ {6,7,8,9}。
- **UI(步进卡,无复杂动画)**:
  - 顶部模式开关:「演示(固定例)| 实占(随机)」。演示模式用引擎内一组固定分点序列,任何人任何时候步进结果一致(可写进单测);实占模式 `crypto.getRandomValues`,旁注小字"此为随机起卦,仅供体验古法"。
  - 主区:当前变的数字过程一行一步("四十九 → 分二:左 24 / 右 25 → 挂一 → 揲四:左余 4 / 右余 1 → 归奇 9 → 余四十"),蓍草用 SVG 小圆点行可视化数量;「下一步 / 快进此爻 / 重新起卦」三按钮。
  - 右侧:已成之爻自下而上排(6 标"——✕ 老阴"、9 标"—— ○ 老阳"……),**让人看见"动爻为什么是六和九"**。
  - 成卦后:显示本卦 + 老阳老阴即动爻 → 主按钮「在工作台打开此卦」(带 gua+dong 参数跳转)。这是学堂与工作台的闭环。
- 配文:开头引《系辞》原段(ClassicText,链接到系辞阅读页),两段白话讲流程,一句说明概率不均(老阳多于老阴)是古法特征。
