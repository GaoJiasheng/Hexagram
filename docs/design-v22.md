## 0. 目标与定位

- **受众**：完全没读过古文的小白。目标是「看完这一章，能用大白话讲明白它在说什么」。
- **形态**：每章一个**默认折叠**的「白话」模块，点开才展开一篇文章级长文。折叠态只占一行，不抢原文/译文/注疏的观感。
- **内容**：以**当前章原文**为底，**章章拆解、句句拆解**，像公众号文章一样把这一章的主体讲透。
- **铁律**：白话只是「另一副更亲民的面孔」，**不另起一套说法**——不得与站内既有译文/注疏冲突，且继承各组红线（见 §3.6）。

> 一句话定位：**把站内已有的「原文+译文+注疏+延伸+源流」，重新熔成一篇小白也能一口气读完的白话长文。**

## 2. 产品形态（轮廓，落地期再细化）

> 本期重点是**内容规范**；UI 仅定方向，避免现在过度设计。

- **入口（默认折叠条）**：每章阅读页放一个**低调的折叠入口条**——一行高，左侧组朱印 + 亲民名「白话论语 · 学而第一」，主色取组 accent（复用 v1.57 朱印体系）。折叠态几乎无存在感，**不抢原文/译文/注疏的观感**。位置：章末（延伸/义理互见之上）；可另在工具条挂一个常驻小按钮，便于随时唤起。
- **打开形态（侧抽屉 / 全屏浮层）**：白话是 5000–10000 字的长文，**不在原文页内联展开**（否则整页被淹没）。点击入口条后——
  - **桌面端**：从**右侧滑出抽屉**（约半屏宽、可滚动、有像样的阅读宽度），**左侧原文仍在，右侧读白话，正好原文↔白话对照**；
  - **移动端**：无并排空间，**全屏浮层**打开（沉浸阅读），关闭即回原文页。
  - 抽屉/浮层内是排版良好的长文（标题分级、引文块、随文 SVG 图）。这就是 owner 「折叠放侧面」的落地：**折叠入口 + 侧抽屉**。
- **持久 / 固定能力（owner 强调：深读不被自动折叠）**：折叠只是「日常不打扰」的**默认态**；一旦打开，抽屉/浮层**只手动关闭，绝不自动折叠、不因翻页/失焦自动消失**。并提供**「展开为整页研读」**——想细读时一键切到**独立整页**（如 `/<corpus>/<slug>/baihua`）：整屏宽度、可收藏/分享/深链、刷新仍在。即「想详细研读时，它能稳稳钉住」。
- **不抢观感**：原文页永远只多一个条；长文有体面的阅读面；对照读是白送的好处。
- **数据层**：新增 `src/data/<corpus>/baihua/<slug>.json`（道藏走 `src/data/dao/baihua/`），按 `slug → 章号 → { body: markdown 正文, figures: [ {id, type, svg, caption, source} ] }`。形态参照 `yanyi.json`，但每条是**整章长文 + 随文配图**而非短锚注。
- **渲染**：白话正文用受控 markdown 渲染（标题/引文/列表）；正文以占位锚 `[图:id]` 引图，渲染器替换为 `<figure>`（内联 SVG + 说明）；引文块复用站内原文样式。**配图能力是本期硬需求，详见 §3.7。**
- **可达性**：折叠块带 aria、键盘可开合；长文懒加载（按需取该章 baihua）。

## 3. 写作规范（**本稿核心**）

> **最高原则（owner 强调）：这首先是一篇「公众号文章」，不是逐句翻译作业。**
> 灵魂是——**大白话把中心思想讲透 + 人人（下里巴人）都跟得上的「脑回路」（把古人的思路翻成现代人的推理链）+ 接地气的比喻**。
> 逐句走读只是其中一环，**为讲透中心思想服务，绝不喧宾夺主，更不能沦为「一句原文一句翻译」的机械清单**。
> 检验标准：读完的人记住的应该是「**这章到底在说啥、戳中了我哪一下**」，而不是「每个字怎么训诂」。

### 3.1 脊柱：每篇必备段（顺序固定）

1. **导语 hook**：一句话点出「这一章到底在纠结什么」，给读下去的理由。
2. **共情入口**：从一个**谁都遇到过的现代瞬间/场景**切入（范本：「心里清楚、一开口就变味」）。先共情，再进原文——降低小白门槛。
3. **立骨架**：本章出处、在全书的位置、核心命题、关键句、生僻字注音。**直接复用站内数据**（题解/源流/注疏）。
4. **逐句走读（穿插，服务中心思想 · 不喧宾夺主）**：顺着原文把**每一句 / 每一意群**走一遍，但每走一句都**落回大白话与中心思想**——引原文句（逐字取站内原文）→ 一句大白话（与站内译文一致）→ **用现代脑回路 / 比喻讲透它在说什么、为什么、易误读在哪**。**不是逐字训诂清单**；讲不出新意的句子可并讲或一笔带过，**把笔墨留给真正需要展开的那几句**。
5. **中心思想贯通（重头戏）**：把全章拧成**一句话能复述的中心思想**，用大白话 + 比喻讲到「下里巴人也点头」；逐句走读拆出的点，都收束到这条主线上（避免只见树木不见林）。
6. **落地**：给小白 **1–3 条**可带走的启发。**守红线**：不鸡汤、不成功学、不算命断事、不诊疗（见 §3.6）。
7. **收束**：**首尾呼应**，回扣开头那个共情入口。
8. **原文出处与参考 + 配图说明**：引文出处到章、版本要点、如实标注分歧。

### 3.2 可选纵深层（**按章选用，绝不强凑**）

只有当这一章**确实有料**时才加，否则省略：

- **源流 / 版本**：有版本差异才讲（如道德经「恒→常」避讳、帛书/楚简）。
- **注释分野**：有两条以上主流解才讲（如河上公「养生治国」 vs 王弼「以无为本」）。
- **时代背景**：思想史动因（如老子针对「礼崩乐坏、诸子正名」）。
- **当代回响 / 跨典互见**：与别家经典对读（**复用 `concepts.json` 跨派概念**），或现代学科呼应（地图非疆域、维特根斯坦…）。
- **比喻系统**：为抽象命题造一个贯穿全文的现代比喻（范本：地图/疆域、渡河之船）。

> **判断标准**：每个纵深层都要回答「小白读了这层，对理解**这一章**有没有实质帮助？」没有就删。宁缺毋滥。

### 3.3 篇幅与节奏

- **主band：5000–10000 字（含逐句拆解在内）**，随原文长度/密度伸缩：
  - 中等（道德经一章/论语数则/一篇短文）：**5000–8000 字**。
  - 长篇（庄子单篇/坛经品/长论）：**8000–10000 字**，过长者**分上下两篇白话**（按原文自然段切）。
  - **短经 / 短章允许降低篇幅**（owner 定）：极短者（心经、几十字的短章/单条爻辞）降到约 **2500–4000 字**即可，**宁可短、不许注水**——把该讲的讲透就收。
- **主体是「大白话讲透中心思想 + 脑回路 + 比喻」**；逐句走读穿插其中、服务主线，**不必占满、不求逐字**；纵深层是配菜。
- **显式分层分节**：让读者随时知道「在第几步」（范本用「第一层/第二层…」）。

### 3.4 语言与风格

- **大白话第一**：能用口语就不用术语；非用术语，当场用一句话解释。
- **引经据典要克制**：每条引证都短、都为当前论点服务，绝不掉书袋。
- **两大核心技法（非可选，是魂）**：
  - **脑回路**：把古人的思路**翻译成现代人能一步步跟上的推理链**——「他面对什么问题 → 为什么这么想 → 所以得出啥」，让下里巴人也能跟着想一遍，而不是直接抛结论。
  - **比喻**：为**每个抽象命题造一个接地气、人人秒懂的比方**（范本：地图≠疆域、渡河之船、两只眼睛看有无）。抽象处必有比喻落地。
- **辅助技法**：共情先行 · 首尾呼应 · 母题复现。
- **形式可呼应内容**（能做到则佳，不强求）：如讲「语言抓不住道」时，文章本身就示范一次「换个说法意思就跑偏」。

### 3.5 引证与诚实（**硬约束**）

- **原文引用必须逐字取站内管线原文**（严禁手改、严禁凭记忆补写）；白话直译须与站内译文一致。
- **出处到章**；版本要点标明；断句公案、异解**如实标注分歧，不替读者拍板**。
- **不杜撰史实、不编造出土文献/译本**。所有「联网核对」类陈述，须真的可核。

### 3.7 配图规范（**流程/对比/列举优先 · 硬需求**）

> owner 定调：**需要图的地方就生成图**，尤其**流程类、对比类、列举类**——有图更直观、更有说服力；站点要能展示；原则**清晰、直白、不突兀**。

**何处配图**（图比文更直观时才出；纯叙述能讲清的不硬塞）：

| 类型 | 用在哪 | 形态 |
|---|---|---|
| **流程 / 时间线** | 文本流变（郭店→马王堆→王弼）、由浅入深的层级、步骤序列、因果链 | 节点 + 连线 + 箭头（横/纵） |
| **对比** | 两解并列（河上公 vs 王弼）、古义 vs 今义、两视角（有/无）、恒 vs 常 | 双栏对照 / 分屏卡 |
| **列举** | 「道」的几种讲法、核心概念清单、结构拆解 | 编号卡片网格 / 放射 / 树 |
| **金句卡** | 一句原文 + 译文 + 《书·章》 | 衬线居中 + 朱印（复用 `QuoteCard`） |
| **结构图** | 一章/一书骨架与关系（如 有/无 → 玄 → 众妙之门） | 关系图 |
| **公版插画**（点缀，非图表） | 老子像、书影等 | **仅取公有领域**（Wikimedia PD），**下载到本地嵌入**、不外链，注来源与授权 |

**出图政策（owner 定「金句卡 / 结构 / 时间线都要」，但须诚实、不凑数）**

- **金句卡**：**每章必出 1 张**（每章都有一句可立的金句——本章关键句 + 白话 + 《书·章》）。
- **结构 / 列举图**：**按内容出**——绝大多数章都有可结构化的要点（核心命题、几种讲法、有/无之类关系），有则出，通常每章 1–2 张。
- **时间线**：**仅当该章确有版本流变 / 历史脉络时才出**（如道德经「恒→常」、文本流变郭店→帛书→王弼）；**没有这条线就不出，绝不为凑图编造时间线**（守 §3.5 诚实铁律）。换言之「时间线都要」= 凡有流变处都要配，而非给每章硬塞。
- **合计**：每章约 **2–5 张**，随篇幅；图直接生成补齐，不留占位空figure。

**生成机制：SVG 优先，不用 AI 栅格做图表**

- 图表一律**生成内联 SVG**：用站内 CSS 变量着色（`--ink`/`--paper`/组 accent），**light/dark 自适应**、矢量清晰、可访问（`<title>`/`<desc>`）、响应式（`max-width:100%`）。与站内既有图（辩论圆桌、卦象图、先天方圆图、金句卡 `QuoteCard`）**同源同构**，最贴合「清晰、直白、不突兀」。
- **不用 AI 写实栅格图做图表/示意**——既不精确也不克制，会破坏纸墨观感。装饰性写实插画**只取公有领域作品**、不自行 AI 生成。
- **公版插画须下载到本地作站内资源嵌入**（如 `public/baihua/<corpus>/<slug>/*.jpg`），**严禁外链热链**（owner 定：能下载下来就用、个人学习非商用；只是 link 到外部就不用）。每图注**来源 + 授权**（PD / CC0 等），可核。
- SVG 不写死颜色（走 `currentColor` / CSS 变量），故一份图自动适配明暗两色与各组主色。

**「不突兀」硬原则**

- 站内 token 着色、充分留白、衬线标注、线条克制（1px hairline）、单点强调色（组 accent），**不做花哨信息图**。
- **图只在该出时出**：一章建议 **2–5 张**（随篇幅伸缩），不堆砌；纯叙述段不配图。
- 每图配一句 `figcaption`（讲清它在说什么）＋出处（引文/数据来源到章）。
- 折叠态不渲染图；展开后图随文出现在「需图处」，懒加载。

**站点展示能力**（落地期实现，本稿先定接口）

- 白话数据层每章带 `figures: [{ id, type, svg, caption, source }]`；正文用占位锚 `[图:id]` 引用。
- 白话渲染器把 `[图:id]` 替换为 `<figure>`＝内联 SVG ＋ `<figcaption>`；响应式、明暗自适应。
- 校验：`check-data` 核对「正文引用的 `[图:id]` 与 `figures` 一一对应、无悬空」、SVG 无写死前景色（鼓励 `currentColor`/变量）、装饰图标注公版来源。

## 4. 与站内既有数据的关系

- **消费既有数据**（既省力又保一致）：
  - **逐句注疏**（zhushi-anchored / corpus 注疏）→ 喂「逐句拆解」的字词。
  - **延伸 yanyi** → 喂「主题贯通/纵深层」的思想点。
  - **源流页 / 题解 authorNote** → 喂「立骨架 / 版本源流」。
  - **concepts.json** → 喂「跨典互见」。
  - **booksIndex** → 文中他书书名自动成链。
- **一致性铁律**：白话**不得与既有译文/注疏冲突**；若白话写作中发现既有译注有误，**先改数据、过 check-data，再写白话**，不在白话里另开一说。
- **与「延伸」的区别**：延伸是脱锚短注（registry，章末几句）；白话是**整章长文**，定位不同、并存不冲突。

## 5. 生产工序（skill / workflow）

沿用站内成熟的并发 workflow 模式（debate/zhuzi 同款：schema 强约束 + 引文逐字校验）。

- **输入**：一章 `(corpus, slug, 章号)` → 取该章 **原文 + 译文 + 注疏 + 延伸 +（题解/源流）**。
- **流程（拟四段 pipeline）**：
  1. **起草 agent**：据真原文，按 §3 模板逐句成文（schema 约束：脊柱段齐备、逐句覆盖、篇幅达标、纵深层按需），并在「需图处」标占位 `[图:id]` ＋ 注明图类型/数据/说明。
  2. **制图 agent**：按占位产**内联 SVG**（遵 §3.7：token/`currentColor` 着色、响应式、可访问、明暗自适应；流程/对比/列举为主），schema 约束图类型与数据正确。
  3. **校对 agent**：① 引文逐字比对站内原文（子串校验，仿 debate cite）；② 红线扫描（按组 §3.6）；③ 与站内译文一致性；④ 篇幅/结构核查；⑤ **配图核查**——`[图:id]` 与 `figures` 一一对应、图中数据（年代/对比项/列举项）与正文及原文一致、装饰图仅公版。不过则打回。
  4. **编者 agent**：润色统一 voice、补共情入口与首尾呼应、定图序与 `figcaption`、出参考。
- **产物**：`src/data/<corpus>/baihua/<slug>.json` 的该章 `{ body, figures }`。
- **校验**：新增 `check-data` 项——脊柱段齐备、引文子串命中、红线词扫描、篇幅区间、与译文不矛盾抽查、`[图:id]`↔`figures` 对应且无悬空、SVG 不写死前景色。
- **批量**：一组一本逐章并发；token 估算参照内容工序经验（~50–55 token/原文字，但白话是「原文字×文章倍率」，单章估 1–2 万字成品 ≈ 数十万 token，**须分批**）。

## 6. 样板片段（套模板示意 · 以《论语·学而》首章证「跨书通用」）

> 仅示意 voice 与结构骨架，**非全文**；正式产出须取站内管线原文逐字、并扩到目标篇幅。此处守**儒组红线**：思想史视角、不作成功学。

**白话论语 · 学而第一**

> 导语：《论语》第一句不是什么大道理，是三个「不亦……乎」。两千年来被刻进课本，却也最容易被读成一碗鸡汤。这篇把它从「背诵默写」读回「孔子到底在高兴什么」。

**一、先说一个谁都有过的瞬间** —— 你有没有过：学一样东西，当时记住了，过段时间再用上、发现「原来真是这么回事」，心里那一下的踏实？孔子开篇说的「说（悦）」，就是这一下。

**三、立骨架** —— 出处：《论语·学而》首章，全书第一则。关键句：「学而时习之，不亦说乎？」核心字：**习**（不是「复习」，本义近「实践、操演」）、**说**（同「悦」，喜悦）。（字义取站内注疏。）

**四、逐句拆解（节选一句示意）**

> 原文：**子曰：学而时习之，不亦说乎？**
> 大白话：孔子说，学了东西、还能时常拿出来实践，不也很让人高兴吗？
> 展开：这里最常被读偏的是「**习**」。今天一看「学习」「复习」，就以为孔子在劝你多刷题——其实「习」的老意思更接近**「上手去做、反复操演」**，《说文》讲「习」从「羽」，本是小鸟反复试飞。所以这句不是「学完再背一遍」，而是**「学到的东西，能在真事上反复用起来」**——那种「学的真派上用场了」的踏实，才是孔子说的「悦」。一字之差，整句的气质就从「苦学」变成了「学以致用的快乐」。这也顺带提醒：**读古书最忌拿今天的词义硬套**（这正是《道德经》第一章也在说的事）。

**……（「有朋自远方来」「人不知而不愠」二句同法逐句展开）**

**五、主题贯通** —— 三句连起来看，是一条由内而外的线：自己学得有得（悦）→ 同道相聚（乐）→ 别人不懂我也不恼（君子）。孔子把「学」的快乐、「友」的快乐、和「不被理解仍自处」的从容，摆成《论语》的第一块基石……

> `[图:san-le]` —— **列举/递进图**（SVG）：三枚卡片由内而外排列「悦（学有所得）→ 乐（同道相聚）→ 君子（人不知而不愠）」，底部一行小字「共同点：根都在自己这边」。组 accent（观仁绿）着色、明暗自适应。`figcaption`：「《论语·学而》首章的三重快乐，层层向外、却同一根本。出处：《论语·学而》。」
>
> 这一处正是 §3.7 说的「**列举/流程类用图更直观**」：三句的递进关系，画成三张卡一目了然，比纯文字省一半口舌，又不突兀。

> 落地（守红线，不成功学）：它不是教你「努力就会成功」，而是说一种**不依赖外部认可的、稳的快乐**——学有所得、与人相得、不得人知亦不愠。这三种快乐，有一个共同点：**根都扎在自己这边。**
