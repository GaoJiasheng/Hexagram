# iPad / App 化方案:让它像 App,而不是装在壳里的网页

> owner 2026-11-09:「iPad 版本感觉还是个网页……首页能不能更 App style;不局限于首页,整体分析怎么以最低成本做 App 移植,
> 又易用易读,还要保证扩展性和兼容度。」
> **本稿是分析与方案,未开工。** 文末 §6 等你圈。

## 1 · 结论先行

**不换技术栈、不重写页面,只加一层「App 外壳」。** 现在 iPad 像网页,根因不在内容页,而在外壳:它拿到的是**桌面网站的外壳**
(顶部链接栏 + 版权页脚 + 一张三屏长的首页)。把外壳按「形态」切开——网页一套、App 一套——内容页一行不动,
iPad、iPhone、安卓平板、将来的 Mac 版都从同一层受益。量级约一周,分三档,第一档(2–3 天)就能把「网页感」去掉大半。

## 2 · 现状实测(iPad 竖屏 834×1194,本地预览量的)

| 看到的 | 实测 | 为什么像网页 |
|---|---|---|
| 首页 | 整页 **2.9 屏**高;先是给新访客看的宣传文案(「古书原文,一句一句读明白」+ 缘起),书架在第一屏下半才开始 | App 的首页是「我的书房」,一屏内能看全、能直接点;宣传文案是给搜索引擎来的陌生人看的 |
| 导航 | 底部标签栏**只在 ≤600px 才出**;iPad 走的是桌面那套:顶部一行文字链接(经典 / 学脉)+ 三个小图标 | 没有固定的「家」,每进一层都靠顶栏和浏览器式的返回 |
| 页脚 | 每页底部都有「观象 · 个人学习站 / 本站为个人学习用途…关于本站」 | 版权页脚是网站的标志,App 没有 |
| 可点区域 | 首页 42 个可点元素里 **13 个高度不到 32px**;阅读工具条按钮 32px | 苹果的指引是 44pt;手指点小链接要瞄 |
| 换页 | 只有淡入(`page-fade-in`),没有「推进 / 退回」的方向感 | App 进一层是从右推入、返回是退回去 |
| 选章 | 阅读页在 <1024px 时目录侧栏隐藏,换成一个下拉框(`<select>`) | 系统下拉框是典型的表单控件 |
| 细节 | 界面文字能被长按选中、整页能被拉出回弹、点按有灰色高亮 | 都是浏览器默认行为 |

**已经做对的(不用动)**:阅读页本身——正文栏宽 695px、行高舒服、译文对照、段级续读;Capacitor 8 外壳、离线内容、状态栏与刘海安全区、
左缘右滑返回、深链、分享、长按图标快捷入口、明暗主题。所以要补的是**外壳和首页**,不是内容。

## 3 · 路线选择:为什么不重写

| 路线 | 成本 | 结果 |
|---|---|---|
| 原生重写(SwiftUI) | 数月;此后每个功能写两遍(网页 + App),80 本书的阅读器、白话、交互件全部重做 | 手感最好,但等于另起一个项目 |
| React Native / Flutter | 同样是重写,且网页端保不住 | 不考虑 |
| **保持 Capacitor,加 App 外壳层(推荐)** | 约一周;一套代码 | 外壳、导航、转场、首页达到 App 观感;正文滚动阅读本来就是阅读类 App 的常态 |

## 4 · 做法:一层外壳,三档内容

### 4.0 地基:形态只判断一次(扩展性与兼容度都靠它)
现在「手机还是桌面」散落在 40 多条 CSS 断点里(600 / 640 / 768 / 1024 各有),iPad 正好落在缝里。改成在根节点上标两个属性,**全站只在一处判断**:

- `data-shell = app | web`:Capacitor 里、或网页被「添加到主屏幕」独立运行时是 `app`,普通浏览器是 `web`
- `data-form = phone | tablet | desktop`:按可用宽度算,窗口变了跟着变(iPad 分屏、台前调度缩成窄条时自动变手机形态)

之后所有 App 化样式都写在 `[data-shell="app"]` 之下:
- **网页端零变化**——SEO、桌面浏览器、刚做完的搜索引擎收录都不受影响;
- **加新组 / 新书零改动**——标签栏和首页格子从 `registry.js` 派生,和现在加站一样;
- **新设备不用再适配**——安卓平板、Mac(以 iPad 应用运行)、折叠屏,都只是 form 的不同取值;
- 浏览器里加 `?shell=app` 可强制进 App 外壳,我能在本地直接验,不必每次打包。

### 4.1 第一档 · 外壳(2–3 天,观感变化最大)
1. **固定导航**:iPad 横屏用**左侧栏**,竖屏和手机用**底部标签栏**。五个固定入口:书房(首页)· 接着读 · 搜索 · 索引(名句 / 人物志 / 时间轴 / 争鸣)· 我的(足迹、统计、设置、账号)。App 外壳下去掉顶部链接栏和版权页脚(「关于」收进「我的」)。
2. **首页改成「书房」,一屏看全**:左边「接着读」(上次读到的书、章、那一段的首句,一点即回)+ 今日一句;右边十六组书架 4×4 格。834×1194 下不用滚动。宣传文案只留给网页。
3. **去掉浏览器痕迹**:界面文字不可选(正文仍可选、可复制);整页不回弹,只有内容区滚动;点按高亮换成按下态;所有可点区域 ≥44pt;悬停提示全部有点按版本。
4. **选章**:下拉框换成从侧边滑出的目录面板(复用已有的目录组件)。

### 4.2 第二档 · 导航手感(约 2 天)
5. **推入 / 退回转场**:进一层从右推入,返回反向。用浏览器自带的视图过渡(iOS 18 起支持),老系统自动退回现在的淡入。
6. **返回时回到原位置**:从章节退回目录、从书退回书架,停在离开时的滚动位置。(现状没有专门处理,懒加载页面返回后是否回到顶部我还没实测,开工时先验。)
7. **每个标签记住自己的位置**:从「索引」切到「书房」再切回来,还在刚才那一页。
8. **iPad 横屏分栏**:书页左边章目、右边正文,点章不换页(像系统的「图书」和「备忘录」)。阅读页 ≥1024px 已有目录侧栏,把它提前到书页即可。

### 4.3 第三档 · 原生细节(1–2 天,可选)
9. 触感反馈(切标签、点亮透镜时轻震)· 外接键盘快捷键(⌘F 搜索、←/→ 翻章、⌘, 设置)· 触控板指针悬停 · 启动画面直接接骨架屏。

### 不建议做
- 仿真翻页 / 把正文改成左右翻页:要重做分页、注疏锚点、段级续读,成本高,且与「逐段对照读」的形态冲突。
- 给每个页面单独画 iPad 版式:违背「一层外壳」的初衷,以后每加一页都要画两遍。

## 5 · 风险与验证
- **只影响 App 外壳**:所有改动挂在 `data-shell="app"` 下,网页端有现成的 616 个测试和 check-links 兜底。
- **我能验的**:浏览器里用 `?shell=app` + iPad / 手机尺寸、明暗主题逐页走查;**我验不了的**:真机上的手感(转场流畅度、回弹、键盘)——走 TestFlight 由你测,和这几次一样。
- **版本**:视图过渡需 iOS 18;更老的系统功能不缺,只是没有推入动画。
- **回退**:一个开关即可把 App 外壳关掉,回到现在的样子。
