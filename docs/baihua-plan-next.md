## 分步方案

### 步骤 0 ·(易经专属)基建预备 —— 仅易经需要,其余直接复用现有管线

易经数据形态与 corpus 站不同(`hexagrams.json` 64 卦,非 `classics/<slug>.json` 章数组),白话管线要补一条 yijing 支线:
1. `gen-baihua-wf.mjs`:加 yijing 分支(读 hexagrams.json,每卦一单元,原文 = judgment + 6 爻);
2. `assemble-baihua.mjs` + `check-data` 的 `chapterText`:加 yijing 源(judgment.original + lines.original 拼接)供引文子串校验;
3. 阅读器接线:`HexagramDetailPage` 挂 `renderBaihua`,App 加 `/hexagram/:id/baihua` 整页路由,`BaihuaBlock` 加 yijing fullPath 特例;
4. 经传(系辞等)走 ClassicsReadPage,另接一遍。

**这是一个独立小工程(~半天代码),建议在动易经内容前单独做、单独验。其余六模块零基建。**

### 步骤 1–4 · corpus 站内容铺开(复用现成编排,逐模块串行)

把 `baihua-step.mjs` 的 `CORPORA` 数组按选定顺序加入新组,编排即自动接力(装配→校验→提交→算下一批→gen→起 workflow),每模块跑完自然进下一个。各模块在 `gen-baihua-wf.mjs` 的 `RED` 表已有对应红线串(中医/法/墨/兵/纵横/谋略全有),无需新增红线代码。

推荐顺序(由「管线现成、铁律相对宽」到「铁律最严/需基建」):

- **步骤 1 · 诸子四家(法+墨+兵+纵横,271 章)** —— 纯思想史铁律,管线最顺,先铺;
- **步骤 2 · 谋略(44 章)** —— 伪书批判铁律,量小,顺手收;
- **步骤 3 · 中医(169 章)** —— 研习不诊疗最严铁律,单独一波、抽查最细;
- **步骤 4 · 易经(步骤 0 基建后)** —— 旗舰,最后做,做完全站九组皆有白话。

### 步骤 5 · 总收官

- 全量 check-data + build + 测试 + 浏览器走查(各新组抽查 hero/图/红线);
- **红线词软警告人工复核**(check-data 的 `⚠ 疑触组红线词` 逐条核,多为「文章明确点破不作断语」的误报,确认即可);
- 更新 CLAUDE.md 当前状态 + design-v22 §8;
- 打 tag、发版。
