## 五、执行机制(怎么接着跑)

生产管线已成熟并硬化,**复用现成编排,改一行即续**:

1. **改范围**:`scripts/baihua-step.mjs` 顶部 `CORPORA` 数组放当前要跑的组(如 `['fa']` 续法家、`['mo']`、`['bing']`…;佛家重做用 `['fo']` 并先清 fo 白话)。
2. **起跑**:`node scripts/baihua-step.mjs` → 它算出下一批(≤10 章)、gen 出 workflow 脚本、打印 `LAUNCH <脚本>`;用 Workflow 工具起它。
3. **接力**:每批 workflow 完成 → `node scripts/baihua-step.mjs <result.json>` 自动:装配 → check-data → 提交 → 算下一批 → gen → `LAUNCH`(或 `DONE`)。逐批起 workflow 即可。

**铁律 / 已固化经验**:
- **串行**:同时只跑一个 workflow,**绝不并行**(并行必撞 API 限流,实测齐发全灭)。
- **CAP=10**:单 workflow ≤10 章 → 并发 ≤10,显著抗限流。
- **坏数据绝不落盘**:assemble 把对不上原文的引文**只剔那一块、保整章**(仅 0 有效引文才整章重生),`snapQuote` 先按标点/汉字回吸——根治了「个别坏引文致整卦反复重生/永久缺口」。
- **断点续跑**:gen 跳过已生成章;`.baihua-attempts.json` 记失败次数,顽固章 3 次放弃并报告(可手动清计数重试)。
- **quota 看护**:逼近 5 小时配额上限(限流变频繁 / `session limit` 提示)就暂停等恢复,别硬撞墙。
- **各组红线**已写进 `gen-baihua-wf.mjs` 的 `RED` 表,无需新增代码。
- **加厚档**:`THICK` 集合里的组走加厚(5–8 图 + 更多生活场景 + 长短分流),目前 `['fo']`;易经走独立 yijing 加厚支线。
