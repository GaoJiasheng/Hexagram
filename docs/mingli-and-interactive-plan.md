## 2. 学习路径:这些书按什么顺序读

这些书**不是平行的**,硬啃《三命通会》必然读不下去。通行的进阶次序,也是板块首页的骨架:

```
 前置知识(学堂 5 篇)
        ↓
《渊海子平》── 入门:术语、歌诀、基本法
        ↓
   ┌────┼────┐          ← 进阶三书,三条不同的路
《子平真诠》《滴天髓》《穷通宝鉴》
  格局      旺衰气势     调候
   └────┼────┘
        ↓
《三命通会》── 集大成:当百科查,不必通读
        ↓
 源头诸书 ── 想知道「这套东西从哪来的」再读
```

**最有意思的知识点在中间那一层**:同一个八字,《子平真诠》问「月令是什么格」、《滴天髓》问「日主强还是弱」、
《穷通宝鉴》问「生在几月、冷还是热」—— **三本书对同一个命例会给出不同的读法**。
这正是「家级导读」该写的那一篇(`school.json`:「子平法是怎么从一条路走成三条路的」),
也天然适合做成**争鸣式的三派对读**。

## 3. 交互与富文本怎么设计(v3 核心)

### 3.0 现状一个数

白话 **2031 篇 · 7915 张图 · 12.6 MB SVG —— 全部是静态的**。富文本模型里「图」只有一种:死图。
读者能做的只有看。这是「看文字、看译注」的根源,也是全站(不只命理)的天花板。

### 3.1 原则一:**书本来的形状,就是它的导航**

很多典籍成书时本来是**表、图、树、网**,只是纸面只能线性排,被压扁了。还原它的形状,比任何装饰性交互都管用。

| 书 | 它本来的形状 | 现在/若套管线 | 还原后 |
|---|---|---|---|
| **《穷通宝鉴》** | **十干 × 十二月 的矩阵**(已验证:全书按「正月甲木…十二月癸水」排,~120 格,每格就是「先用某、次用某」) | 线性长文 | **10×12 可点矩阵**作目录:每格直接显示调候用神(如「三月甲木:先庚次壬」),点进该节。一眼看完全书骨架 |
| **《三命通会》卷八九** | 六十日 × 十二时 的查表(「六甲日甲子时断」…) | 两卷流水账 | 60×12 查表盘 |
| **《滴天髓阐微》** | 三层:纲领句(经)→ 任氏阐微(注)→ 命例(证) | 混排 | 三层折叠:先只见纲领,逐层展开 |
| **《子平真诠》** | 一棵判定树:月令 → 取格 → 成败 → 救应 | 48 篇散论 | **格局判定流程图**,每个节点挂原文出处 |
| **《渊海子平》** | 歌诀 | 散文排版 | 韵文断行(`verse` 现成)+ 歌诀闪卡 |

### 3.2 原则二:富文本里要有**「活的块」**

给富文本块模型加一种 `widget` 块 —— 文章里嵌的不再是一张画死的 SVG,而是一个**带参数的交互件**:

```json
{ "type": "widget", "kind": "sizhu", "props": { "pillars": ["辛卯","丁酉","庚午","丙子"], "focus": ["丁","午"] } }
```

- **作者/管线只写参数,不画图** —— 省 token(一个引用 ~50 token vs 一张 SVG ~800)、风格统一、明暗自适应
- **`check-data` 能校验参数**(四柱必须是合法干支、卦号 1–64)—— 死 SVG 画错了机器查不出,参数错了能查
- **做一次,全站复用** —— 白话、观书、导读、学堂都用同一个渲染器(`BaihuaArticle`),加一种块四处生效
- 旧的 7915 张静态图**不动**,新内容优先用 widget

### 3.3 交互件库:按**知识的形状**分七类

判断一段知识该配什么交互,看它是什么形状:

| # | 知识的形状 | 交互件 | 读者**动什么 → 悟什么** | 命理里 | 其他组 |
|---|---|---|---|---|---|
| 1 | **规则**(输入→输出) | 可拨动的演示器 | 改输入看输出跟着变 → 悟「规则」而非背结论 | **十神盘**:换日主,全盘十神当场重标 → 悟十神是**关系**不是属性;**节气年轮**:拖日期看年柱在立春跳、月柱在节气跳 | 诗词平仄谱;易经已有(工作台) |
| 2 | **对应网**(多维关联) | 联动高亮图 | 点一个,相关的全亮 | **五行生克图**;十二支盘(合/冲/刑连线开关) | 中医五行藏象;八卦取象;佛教名相 |
| 3 | **矩阵/查表** | 可点矩阵 | 一眼看全局,点格下钻 | 穷通宝鉴 10×12;三命通会 60×12 | 本草经 6 部×3 品;六十四卦方图(已有) |
| 4 | **判定/分类树** | 走得通的流程图 | 自己回答问题往下走 | 格局判定;旺衰判断 | 伤寒论六经传变;墨辩推理 |
| 5 | **案例** | **步进走读** | 一步一步揭,每步图上高亮所指 | **命例图**(滴天髓约千例) | 春秋筮例(已有卦例图);韩非子储说「经—说」对应 |
| 6 | **流变/谱系** | 时间轴 / 关系图 | 拖时间、点人物 | 子平法三派分流;大运轴 | 典籍时间轴;儒门学脉;禅宗传灯;诸子拓扑(已有) |
| 7 | **多解并存** | 视角切换 | 同一对象切不同「镜头」 | **三派对读**:同一命例,切 格局/旺衰/调候 三个镜头,各自高亮不同的字 | 诗经毛序 vs 今读;道德经王弼本 vs 帛书;争鸣(已有) |
| + | 记忆 | 闪卡 / 小测 | 提取练习 | 藏干、纳音、十神 | `QuizCard`、卦画闪卡(已有) |

### 3.4 命理板块按学习次序摆出来

```
① 六十甲子盘      转一圈 → 为什么只有 60 种不是 120 种(阳配阳、阴配阴)
② 节气年轮        拖日期 → 年从立春换、月从节气换(初学者头号误区)
③ 五行生克图      点一行 → 生我/我生/克我/我克 四向
④ 起柱演示        选年干 → 十二个月干自动填满(五虎遁其实是个模 10 运算)
⑤ 十神盘          换日主 → 全盘重标                          ← 最关键的一个「顿悟」
⑥ 十二支盘        藏干展开;六合/三合/六冲/三刑 连线开关
   ─────────── 以上是学堂,之后进书 ───────────
⑦ 渊海子平        歌诀断行 + 闪卡
⑧ 真诠 · 格局流程图   自己走一遍取格
⑨ 穷通 · 调候矩阵     10×12 一屏看全书
⑩ 滴天髓 · 命例走读   千例,每例一张可步进的四柱图
⑪ 三派对读        同一命例切三个镜头
⑫ 排盘台          练手:排一个,用上面学到的自己读结构(不出断语)
```

四层文字内容(原文/译注/延伸/白话)照做 —— 它们是知识本体;上面这些是**让人进得去**的门。

## 4. 红线(一段话)

## 8. 风险

- **App**:owner 指出「App 就是 Web 套壳,网站有了 App 自动带上」——**对,而且藏起来反而要多写代码**。
  风险只在审核(送审备注写着 "does not tell fortunes";指南 4.3(b) 点名 fortune telling 为饱和类目),
  但**代价很低**:最坏是某次更新被拒,线上版本不受影响,届时再门控也来得及。**故默认直接带上,不预先藏。**
  v2/v3 以典籍研读为主体,与现有「古籍研读」定位一致,比 v1 的排盘工具安全得多。
- **体量**:光 P2+P3 就 ~72 万字,相当于再做半个现有全站。是大工程,不是小补丁。
- **沉淀期**:四周前定的沉淀期,依据是「零用户,再加书是盲猜」。命理是新入口而非第 75 本书,不矛盾 ——
  但**动工前先看一眼 `/admin/stats`**,这四周有没有人来、从哪来。
