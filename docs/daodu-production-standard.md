# 书级导读「前世今生」· 作业标准

一书一篇，讲**这部书本身的命运**。数据在 `src/data/<corpus>/daodu/<slug>.json`。
样板：`src/data/dao/daodu/daodejing.json`（owner 三轮反馈磨出来的，动手前先读一遍）。

> 这份标准的每一条都是**被否掉一版才写下来的**，不是凭空立的规矩。照做。

---

## 一、体裁：不是内容摘要

owner 的原话：「**我希望它会有作者的东西**：作者的生平经历、写这本书的环境背景和过程，
以及这本书写出来之后的变迁和流传。**最后才是这本书的大概内容**。反而我不是特别需要
你把书的内容在这篇文章里展开……如果我需要更详细的内容，我会点进去看。因为每一章我们已经有白话了。」

所以骨架是：

| 节 | 讲什么 | 分量 |
|---|---|---|
| **其人** | 作者是谁、生平、身份、疑点 | 重 |
| **其时** | 他站在什么位置看世界、当时的世道 | 重 |
| **其书** | 怎么写出来的、成书过程、是不是一时一人 | 重 |
| **其传** | 版本流变、出土、注家谱系、被谁怎么读、走出中国 | **最重** |
| **其旨** | 主要主张 | **几百字，点到为止** |
| **从哪读起** | 推荐入门的几章，收尾 | 短 |

**「其传」是全篇的重心**，通常占三节。义理展开是各章白话的事，这里越界就跑题。

**❌ 反例（第一版被否）**：把八节写成「一、其人 二、其时 三、其书……」，
每节先给结论再举例，读起来像提纲。

## 二、笔法：娓娓道来，不要脚手架

owner 原话：「**格式化太重，显得很刻意**」「我希望的是**娓娓道来**这样一个文章」。

- **小标题要意象化**，不要编号 —— ✅「一个考不出来的人」「两千年后，墓里给出了答案」
  ❌「一、其人：史书没写清楚」
- **`callout` / `list` / `steps` 一律不用**。样板全篇 0 个。这三种块会把散文剁碎。
- 主体是连贯的 `p`。样板 47 段 `p`，段与段之间有承接，不是并列条目。
- `pull` 全篇至多 1 处。

---

## 三、但图与表要给足

owner 原话：「**富文本化做得不够**……用这种富文本的形式（比如图或者表）去表达一下」。

这与第二条**不矛盾**，分寸是：

> **文字型脚手架（框/清单/步骤）少用，信息型富文本（图/表）多用。**
> 图表承载散文装不下的东西（谱系、异文、分岔）；框和清单只是把已经说清的话再框一遍。

加厚档 **4 处以上**（样板 5 图 1 表），`check-data` 低于 3 会告警。什么该画：

| 内容 | 用 |
|---|---|
| 版本谱系、年代流变 | `figure` 时间线 |
| 一源多流（各家读法、一人多说） | `figure` 分岔图 |
| 两方对照（孔老、儒法） | `figure` 对照图 |
| 逐项对照（今本/出土本/差别） | `table` |

**SVG 规矩**（踩过）：
- 着色只能 `style="fill:var(--ink)"`，**不能** `fill="var(--x)"`，更不能写死 `#hex`
  —— presentation 属性不认 `var()`；写死色暗色模式下会瞎。`check-data` 判错。
- 字体 `font-family:var(--font-serif)`。
- **手写坐标必须量过**：样板的传本谱系图底部两行标签基线 286 + 字高超出了 300 的画布，
  被裁掉了。落盘后用浏览器逐个量 `getBBox()` 是否越出 `viewBox`（文字与方框都要量）。

## 四、引文：两层规矩

**这是本体裁与白话最大的不同**，因为大量材料在站外。

| 来源 | 怎么处理 |
|---|---|
| **本书原文** | 作 `quote` 块，带 `cite{corpus,slug,ch,label}`，**逐字命中该章**。`check-data` 校验。 |
| **站外材料**（《史记》《庄子》、出土简帛、注家、史事） | **只在正文里转述并标出处**，绝不作 `quote` 块。`check-data` 对无 `cite` 的 quote 直接判错。 |

**引文一律脚本切片，严禁手打**（站内老规矩，栽过十几次）。写之前先跑一遍：

```bash
python3 -c "
import json
d=json.load(open('src/data/<corpus>/classics/<slug>.json'))
ch={c['no']:''.join(p['original'] for p in c['paragraphs']) for c in d['chapters']}
for q,n in [('要引的句子',章号)]: print(('✓' if q in ch.get(n,'') else '✗'), n, q)"
```

站外史实按站内既定的**四级分级**（v9 §4）：共识直写 / 有考证的标出处 / 存疑的明示 / 拿不准的宁缺毋滥。
不确定的年份、排名、首译者一律**不给确数**（样板里「被译成外文最多」就只说分量、不给排名）。

`refs` 块收尾，把「哪些是站内原文、哪些是站外转述、哪些仍有争议」交代清楚。

## 五、厚度分档

| 档 | 字数 | 判据 | 例 |
|---|---|---|---|
| 厚 | 6000–8000 | 有出土翻案或学术公案 | 道德经 · 论语 · 孙子 · 坛经 · 墨子 |
| 中 | 4000–5000 | 有作者生平、注家谱系、版本流变 | 大学 · 列子 · 伤寒论 |
| 薄 | 2500–3500 | 短经、托名，材料少 | 八大人觉经 · 止学 |

**薄档不等于没料**。谋略五部伪书字数少，但「谁在什么年代造的、为什么托来俊臣冯道的名、
怎么流行起来的」恰恰是最好的前世今生 —— 与站内伪书批判红线同一路。

## 六、红线（按组，与白话同一套）

| 组 | 红线 |
|---|---|
| 道 | 不宗教宣化；不下吉凶/福报/成仙断语；不演内丹工法；真伪如实 |
| 佛 | 研习不宣化；不下果报/往生断语；不劝皈信 |
| 儒 / 心 | 思想史视角；不作现代成功学、鸡汤发挥 |
| 法 墨 兵 纵横 | 思想史视角；不作权术教程、不作兵法实操、不作现代政治影射 |
| 中医 | **研习不诊疗**。医史源流、成书流传属文献史，可写；不述功效用法用量、不下疗效断语 |
| 谋略 · 伪书 5 部 | 批判框架：点破托名、拆其偷换；绝不为伪书张目 |
| 谋略 · 真书 4 部 | 长短经/菜根谭/围炉夜话/小窗幽记**不套伪书框架**，取思想史与处世研习视角 |

宗教史实（如老子被神化为太上老君）**如实记录 ≠ 宣化**，写清「这是后世的信仰建构，
与这部书讲了什么是两回事」即可。

## 七、一书多 slug

《庄子》在站内拆内/外/杂三部，《黄帝内经》拆素问/灵枢 —— 各自**本是一本书**，
前世今生同一套。**只写一篇**，其余 slug 写：

```json
{ "aliasOf": "zhuangzi-neipian" }
```

构建期展开成同一份文件，`check-data` 只校验目标存在。

## 八、十步清单

1. `git log` / 读样板 `dao/daodejing.json`，找准体裁手感
2. 定档（厚/中/薄）与该书的红线
3. **先跑引文切片脚本**，把想引的句子逐条坐实为站内原文子串
4. 查这本书的来路：作者生平、成书、版本、出土、注家、影响；拿不准的**宁缺毋滥**
5. 写正文（意象化小标题、连贯 `p`、0 callout/list/steps、≤1 pull）
6. 配 4 处以上图表，SVG 用 `style=` 不写死色
7. 落盘 → `node scripts/build-content-assets.mjs`
8. `npm run check-data`（引文子串 / 图表数 / SVG 颜色 / 表格列数）
9. **浏览器逐个量 SVG 几何**：文字与方框不得越出 viewBox
10. `npm run build && npm test` → commit
