## 1 · 逐条核对与方案

### T1 大陆手机实测(owner)

- 我从这里测:DNS 2ms / TLS 124ms / 首字节 200ms / HTML 4.7 KB。这只证明服务器不慢,**证明不了大陆手机的体验**。
- 大陆访问 Cloudflare Pages 的问题是 anycast 节点时好时坏、偶发整站超时,与页面多大关系不大。**根治是 O8 ICP 备案 + 国内 CDN**,短期能做的只有减字节、去外链、让失败也能显示东西。
- 建议测法(一次 5 分钟):关 Wi-Fi 用 4G,依次开
  `https://hexa.gavin.pub/`、`/hexagram/4`、`/ru/lunyu/1`,记「几秒出字、字体有没有闪一下、有没有 5 秒以上白屏」;
  在 `/ru/lunyu/1` **试注册一个邮箱账号并发一条评论**(这一步同时测 Turnstile,见 T10);
  再**从微信里点同一个链接**开一次(大陆手机最常见的入口是微信内置浏览器,见 §2 S1)。
- 测不达标 → T2 方案 A 升为必做。

### T2 字体与首屏体积(已核:两条建议已是现状)

线上首页首屏实测(内置浏览器,冷缓存):

| 类型 | 请求数 | 传输 | 解码后 |
|---|---|---|---|
| woff2(Noto Serif SC) | 32 | 1.19 MB | 1.18 MB |
| JS | 18 | 0.16 MB | 0.47 MB |
| CSS | 1 | 0.11 MB | 0.55 MB |
| 合计 | | **≈1.46 MB** | 2.2 MB |

- 32 片里 24 片是 400 字重、8 片是 600 字重(标题)。fontsource 把 CJK 切成 120 片按 unicode-range 按需载,首页命中 32 片是因为首页汉字散得开——**再切没有意义**。
- `font-display: swap` 与 `/assets/*` 一年 immutable **都已在**(fontsource 400.css 自带 swap;`public/_headers` 早就写了)。对方看到的 `max-age=0, must-revalidate` 是 index.html 的头,入口文件本就不能缓存。
- 真正的杠杆是**哪些页面才值得下 1.2 MB 字体**:
  - **方案 A(推荐)**:门户/首页/组首页用系统衬线兜底(`"Songti SC","STSong","Noto Serif CJK SC",serif`),**只有阅读页才加载 Noto**;标题 600 字重延后到 idle。首页首屏字体 0 字节,总传输 ≈0.27 MB。代价:iPhone 有「宋体-简」观感几乎一样;**安卓多数没有衬线中文字体,会回落到黑体**,首页与阅读页字体不一致——这正是 T1 该看的:老师用的是 iPhone 还是安卓。
  - **方案 B(保守)**:全站照旧,只把 600 字重延后到 idle(省 ≈30%,首屏 ≈0.9 MB)。
- 验收:方案 A 首页首屏 ≤0.5 MB;方案 B ≤0.9 MB。

### T3 Cloudflare Web Analytics(owner 一键)

线上 HTML 里确有 `<script defer src='https://static.cloudflareinsights.com/beacon.min.js'>`,**不在 dist 里**,是 Pages 项目「Web Analytics」开关自动注入的。`defer` 不阻塞渲染,大陆超时只是统计丢失。你不看这个面板的话,Pages 后台关掉即可;要留也无妨。

### T4 首屏「灯」还是「仪表盘」(owner 拍板)

现状首屏(手机一屏):朱印「观象」→「83 部典籍,逐字校过的白话」→ 一行说明 → 四个数字(83 / 2,371 / 88 / 1,236)→ 一行「引文全部逐字校验…」。对方说得对:**这是给同行看的**。「白话」「逐字校验」「跨派对辩」对语文老师都是术语。

三个选项:
- **A(对方原案)**:首屏换成跋里「缘起」三段。我的顾虑:三段手机放不下一屏;第三段讲「大模型分担案头之劳」,要不要在老师看到的第一眼就说,你定。
- **B(折中,我推荐)**:首屏 = 朱印 + 一句人话的主张(例:「把值得留住的古书,一句一句读明白」)+ 缘起第一段(两句,少时读国学…)+「读全文 → 跋」;四个数字**下移到「索引」段**(那里本来就是计数区)。手机首屏不滚动即见缘起句与一个「进去读」入口。
- **C(最小)**:首屏不动,只在数字下加一行缘起第一句 + 「跋」链接。

无论选哪个,**「83 部典籍,逐字校过的白话」这句 hero 标题**建议改成给外人看的话。

### T6 《滕王阁序》与「古文」这一栏(owner 定 A/B)

核实:站内没有;「落霞」命中的是元曲注疏与《小窗幽记》白话里的引用。老师会找它,也会找岳阳楼记、醉翁亭记、赤壁赋、师说、陈情表、出师表、归去来兮辞、兰亭集序、桃花源记——**她要的不是一篇,是「课本上那些古文」**。

- **不建议**挂唐诗三百首「补遗」(你昨天刚定唐诗是定本、一组一本书)或临时建一个只有一篇的组。
- **方案 A(推荐):新组「古文研读」= 《古文观止》一本**。222 篇 12 卷,公版,维基文库有分篇子页(`古文觀止/卷N/篇名`,走 corpus 管线);形态同唐诗三百首(SingleBookHome,一组一本书);三层全做 + 家级/书级导读。课本篇目大半在里面(滕王阁序、岳阳楼记、醉翁亭记、前后赤壁赋、师说、陋室铭、阿房宫赋、出师表、陈情表、归去来兮辞、兰亭集序、桃花源记、捕蛇者说、曹刿论战、烛之武退秦师、邹忌讽齐王纳谏…);不在里面的少数(小石潭记、鸿门宴)另议,愚公移山站内《列子》已有、邹忌《战国策选》已有。
  - 成本:原文 ≈20 万字 → 译注延 ≈10M token、白话 222 篇 ≈7M、导读 ≈0.4M;串行 2–3 天。
  - 骈文/古文与近体诗不同,**格律层不接**;只接韵文断行(骈文可考虑 `verse:true` 按句读断行,先试滕王阁序看效果)。
- **方案 B(便宜)**:新组「古文选」,自选 30 篇课本名篇(≈3M token,1 天)。缺点:选目本身就是一种主张,老师一眼看得出「缺了哪篇」。
- **方案 C(最小)**:只补滕王阁序一篇。不推荐——一个组一篇,比没有更怪。
- **延伸里的那一段**:对方建议写「课堂上老师讲这一句时抬头望向斜上方」——那是**你的记忆**,我不能替你编。我在 `scripts/authored/` 留一个位,你写一段,其余延伸照常由管线产出。
- 「课本篇目」筛选(初中/高中):教材版本不一,要做只能标「以人教版常见篇目为参照,各版本有出入」,或者不做。你定。
- 验收:搜「落霞」「滕王阁」首条命中;手机从首页两次点击可达(门户卡 → 目录 → 篇)。

### T7 句级工具图标(我做,半天)
