## M0 做完后的状态(2026-11-22)

**做出来的**
- 工程:`apps/desk/`(SwiftUI,iOS 17+,`pub.gavin.hexa.desk`);工程文件由 `xcodegen` 从 `project.yml` 生成,`apps/desk/build.sh` 一条命令编到模拟器。
- 内容包:`npm run desk:packs` → `public/desk/v1/`(清单 + 每本一个带内容哈希的包)。五本已出包(道德经 95 KB / 论语 261 KB / 孙子 91 KB / 鬼谷子 96 KB / 庄子 731 KB),逐段核原文、注释词是原文子串。易经数据形态不同,M1 接。
- App 已能:拉书目 → 下载一本书 → 放上书桌 → 翻页阅读(TextKit 多容器分页,记到段)→ 点注释词出注 → 轻点一段展开译文 → 目录跳章 → 章末页(延伸 + 下一章)→ 学完庆祝页。iPhone / iPad 竖屏 / iPad 横屏都能跑。
- 字体:思源宋体(OFL)子集随 App 带,两个字重各 6.5 MB(`scripts/desk/subset-fonts.py`,留 GB2312 + 全站用到的字共 13976 字)。iOS 不预装宋体。
- 调试:本机 `cd public && python3 -m http.server 8765` 给模拟器供包;`SIMCTL_CHILD_DESK_DEMO=seed|reader|finish` 直接进某一屏出样张。

**核出来的事实(登录与同步,后端几乎不用改)**
- 后端已有原生通道:请求带 `X-Client: native`,登录 / 注册 / 重置在响应体里回 `token`;之后 `Authorization: Bearer <token>`,查的是同一张 sessions 表。邮箱登录、注册、验证码、`/me`、`/sync` 原生端可直接用,不涉及 cookie、CORS、人机验证。
- `/sync` 可以只传变动的键;MAP 类键(`readDays` `corpusMarks` `corpusNotes` `bookmarks`)逐条按时间戳合并、删除用墓碑;**未知键整包 400**——加 `highlights` `finished` 必须先发服务端。
- 要改的只有:① `/auth/logout` 现在只读 cookie,Bearer 登出不删会话 ② Google 登录回调只回站内路径、不回令牌,原生要加「回到 App + 一次性码换令牌」③ Apple 登录全新。
- 注销账号 `DELETE /me` 已有。

**owner 在 M0 期间补的要求**
- 阅读页不要电子书那一套:**字要大**(按屏宽自适应,各尺寸 iPad 约 30–34,手机 22 上下)、**纯交互**(默认只显示原文,轻点一段展开那一段的译文)、**不要素**(顶部主题色晕染、章号水印、译文色块、翻页点、题头插画)。已按此改。

- 可以酌情外包给 Opus、Sonnet 和本机 Codex。

**插画实测**:Codex 出一张 1536×1024 约 35–40 秒、约 2 万 Codex token,并发 3 没问题。四种画风样张在 `scripts/.cache/desk-art/samples/`(`node scripts/desk/art-samples.mjs`),**等 owner 挑**;样张里临时用的是「青绿重彩」。

## 2 · 产品长什么样

**书桌(首页)**
- 最上面一条「接着学」:最近那本书、第几章第几段、离上次多久,一点就回到那一页。
- 下面是我订的书,每本一张卡:题图、学到哪、学过几章 / 共几章。
- 「今日一章」:订阅且最近在读的每本书各给出它的下一章。只订一本就只有一张。
- 本周目标的进度环(默认按时长),旁边是本周哪几天学过。
- 「添书」进书目:首发六本,点一下下载内容包,再点一下收起(收起只是从书桌拿走,进度不丢)。

**书页**
- 题图、题解、读法一句;目录(易经按上经 / 下经 / 十翼,庄子按内 / 外 / 杂,论语按篇)。
- 每章标三种状态:没读 / 读到一半 / 学过(满 3 分钟)。
- 我在这本书里的划线与批注入口。

**阅读器**(核心)
- 左右翻页,一屏若干段。一段太长(鬼谷子一段六百多字)时段内续页;进度记「章 + 段 + 段内位置」,换字号、换设备都能落回同一句。
- 原文为主,译文可整体开关,也可点一段单独看;有注释的字词点一下出注。
- 顶上一条细进度线;下拉或点页边出目录抽屉,随时跳章。
- 章末一页:本章学过了没有、这一章的白话深读入口、下一章。
- 全书最后一页:「学完」按钮。点下去是一整屏的庆祝(题图展开、盖一方印、这本书的学习账单:几天、多久、多少字、多少条批注)。

**体裁模板**(编在 App 里,每本书声明用哪种)★ 待确认
| 模板 | 用于 | 特点 |
|---|---|---|
| 短章 | 道德经 | 一章常常一两页;章与章之间翻页即过 |
| 语录 | 论语 | 按条分页,不把一条拆到两页 |
| 卦 | 易经六十四卦 | 卦画常驻页眉;卦辞 → 彖 → 象 → 六爻逐爻,爻位在卦画上点亮 |
| 篇章 | 庄子、孙子、鬼谷子、十翼 | 长段续页,段首有段号 |

**长按**
- 选中字句后出菜单:划线、批注、查本书、查全站、复制。
- 「查本书」在本机搜已下载的内容包,列出全部出现处(章 + 那一句),点了跳过去,回来还在原位。
- 「查全站」用观象现有的搜索索引;搜到没订的书,给「加到书桌」。

**划线与批注**
- 划线可选颜色(三四种),批注挂在划线上。
- 三层都能划:原文、译文、白话。记录页按书、按层分开列,点一条跳回原处。
- 原文哪天因订正改了字,划线靠存下的那几个字重新定位;定位不到的标「原文已改」,不丢。

**白话深读**
- 每章一篇,纵向滚动(长文不适合翻页)。题头一张插画。
- 文内图解用原生重排(见 §6);金句卡是「插画底 + 原生排的字」。

**统计**
- 日 / 周 / 30 天 / 全部:时长、字数、学过的章、划线与批注数;按书拆开。
- 一年热力图;每周目标达成的连续周数。
- 字数口径:一页显示满几秒,这页的原文字数计入;重读不重复计。

**账号**
- 邮箱(密码或验证码)、Google、Apple。不登录可用,数据在本机;登录时与云端合并。
- App 内可注销账号(苹果要求;服务端已有删除接口)。

## 3 · 视觉与手感

- 底色用暖白与浅色纸感,不用观象的墨灰;每本书一个主色(从题图里取),书页、进度环、划线色跟着走。
- 动效克制但处处有:翻页跟手、进度环生长、学过一章时章号落一个小印、学完一本的整屏庆祝。配触感反馈。
- 不做卡通形象、不做积分排行。「激励」落在:进度看得见、连续周数、学完的印章和账单。
- 深色模式同样做,不是简单反色。

**每本书一套「主题」**(owner 11-22 补充:每本古籍要有自己的氛围,可自行设计)
- 一本书一份主题,随内容包下发:主色与辅色、题图、一组装饰件、章首样式、学完时盖的那方印。书页、阅读器的页眉页脚、章末页、庆祝页都跟着换。
- 装饰件取这本书自己的物象,由 Codex 出成成套的小图(不带字):
  - 道德经:水、谷、未雕的木、车辐与器
  - 论语:杏坛、竹简、弦与磬、堂前的席
  - 易经:卦画、蓍草、日月与四时
  - 孙子:山川地形、旌旗、舟车
  - 鬼谷子:幽谷、门扉的开合(捭阖)、绳结
  - 庄子:鲲鹏、蝴蝶、大树、濠梁上的鱼
- 用在哪:书页顶部的大题图、章与章之间的过场页、章首的小饰、空状态、翻到一篇末尾的留白处。正文页保持干净,装饰不压字。
- 也可以有不出自原文的设计,比如每本书一句由我拟的「入门引子」、按书定制的章号样式和过场动效。凡是我方新写的话,都与原文分开标示,不冒充原典。
- 沿用的规矩:不画脸、不画圣贤像;易经不画成算命摊的样子。
- M0 先出三屏原生样张(书桌 / 阅读页 / 学完庆祝)和插画画风样张,owner 挑定后再往下做。

## 4 · 技术

**目录与隔离**
```
apps/desk/                  新 App 的 Xcode 工程与全部 Swift 代码(不引用 ios/、src/ 里的任何代码)
scripts/build-desk-packs.mjs 内容包构建(只读 src/data,产出 public/desk/)
public/desk/v1/             内容包与清单,随网站部署,App 从 hexa.gavin.pub/desk/v1/ 下载
```
- 现有 App(`ios/` + Capacitor)和网站构建不读 `apps/desk/`;书桌的构建不读 `ios/` 和 `src/` 的代码。两边唯一的共同点是 `src/data` 这份内容。
- Bundle ID `pub.gavin.hexa.desk`,版本号独立于网站。★ 待确认
- 最低系统 iOS 17 / iPadOS 17。★ 待确认
- 不引第三方库,除非绕不开(Google 登录走系统的网页登录窗口,不装 Google SDK)。

**内容包**
- 一本书一个包:清单(书名、体裁模板、章目、版本号、字数)+ 各章数据(原文、译文、注释、段号)+ 白话 + 图解的结构化数据 + 插画。
- 清单 `manifest.json` 列出全部可订的书和各自版本;内容订正后版本号变,App 后台更新,进度与划线按段号对得上。
- 构建脚本带校验:段数、段号与 `src/data` 一致;原文一字不差。
- 加一本已有体裁的书 = 构建时多出一个包,不发版。

**本机数据**
- 进度、学习时长、划线、批注、目标、订阅,存本机数据库;每次翻页立即落盘。
- 同步:有变动后十几秒推一次,切后台再推一次;启动与回前台时拉一次。

**与观象数据的对应**
| 书桌里的 | 观象现有的 | 做法 |
|---|---|---|
| 续读位置 | `readPos`(书 → 章、段) | 直接共用,补「段内位置」与设备名 |
| 学习时长 | `readDays`(日 × 书 × 章 × 设备 → 秒) | 直接共用;「学过」= 该章各日秒数相加满 180 |
| 字数 | 无 | `readDays` 条目里加字数一项 |
| 段级收藏 / 笔记 | `corpusMarks` `corpusNotes` | 读得到、显示;书桌里新写的走划线 |
| 划线 | 无 | 新键 `highlights` |
| 学完 | 无 | 新键 `finished`(书 → 时间) |
| 每周目标 | 无 | 进 `settings` |
| 订阅的书 | 无 | 只存本机 |

## 5 · 服务端与网站要配合改的

- **Apple 登录**:新接口校验苹果签发的身份令牌;`users` 表加一列。照规矩,迁移先上远端 D1,再发代码。
- **Google 登录**:沿用现有网页流程,补一个回到 App 的跳转。
- **同步接口**:登记新键(客户端与服务端两处 `DATA_KEYS` 同步加,否则整包 400);支持只推变动的键,保证「密」而不重。现有 `/sync` 的细节 M0 先核。
- **原生端的登录态**:现在靠浏览器 cookie,原生端要能拿令牌;M0 核现有实现后定。
- **网站端显示划线**、**网站加 Apple 登录**:放第二期。
- 这些都改的是现网在用的服务,每一项单独发、单独验,不和 App 开发搅在一起。

## 6 · 配图

**图解(原生重排)**
- 首发六本的白话里有 1296 张图,几乎全是带字的图解。把每张转成结构化数据(类型 + 条目文字),App 里用原生样式画:对比、列举、时间线、结构、流程五六种版式。
- 转换外包给 Sonnet / Opus,机器核「结构化后的字都出自原图,不多不少」;版式不够用的少数图,人工定。
- 引文仍可逐字校验,这是不交给插画的原因。

**插画(Codex 主线)** ★ 待确认其中的「B 怎么落」
- 每本书一套主题图(§3):大题图、过场图、成套装饰件。首发六本约每本 15–25 张。
- A 每篇白话一张题头插画。
- B 图位里适合出画的:我建议落在**金句卡**上——Codex 只画不带字的底图,那句原文由 App 用原生字体排上去。这样既有画,字也不会错。其余纯信息的图位走上面的原生图解。
- 量:首发六本约 260 篇 → 题头 260 + 金句底图约 260;全站 2616 篇 → 各约 2600。
- 流程(全部走脚本):把一篇白话喂给 Codex → 它读懂后设计画面、写 prompt → 出图 → 机器筛(画面里有字的用 OCR 剔掉、尺寸、空白)→ 按书拼样张页 → owner 翻,不满意的单张重出。
- 画风:M0 用《道德经》出三四种带颜色的画风样张,owner 挑一种定为全站统一的风格说明。站内既有规矩沿用:不画脸、佛道不画像、中医不画诊疗、伪书不画气派。
- 顺序:首发六本 → 其余各组。每批开跑前看 Codex 额度,有余量就往下铺。图存进各书的内容包,不动现有 App 和网站。
- 出图速度与每张耗的 Codex 额度没测过,M0 测了再排批次。

## 8 · 风险

- **审核 4.3(重复 App)**:同一开发者、同一批内容、名字还带「观象」。对策是功能定位明显不同,提审备注里讲清;不保证一次过。
- **书房是隐藏功能**:只对管理员账号出现。现有 App 这样过审了,但仍是风险点,放第二期单独评估。
- **原生翻页的排版**:中文长段按屏切分、段内定位,是整个 App 最难的一块,M1 先攻它;做不稳就先退一步(整段不拆、段内滚动)。
- **我看不到真机手感**:转场、跟手程度、触感只能 owner 测;每个里程碑发一个 TestFlight。
- **改现网服务**:登录与同步接口的改动影响网站与现有 App,逐项小步发。
- **插画质量不齐**:几千张不可能逐张精挑,靠统一风格说明 + 机器筛 + 样张页抽看。

- 确认本方案,尤其是标「★ 待确认」的几处。
